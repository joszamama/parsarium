Providence and Pawtucket2 are separately tagged CollectiveAccess application distributions. Each exposes `PlyToStl::convert` from its released `app/lib/Parsers` directory. Their 2.0.12 parser files have the same SHA-256 and passed the local triangle through the same adapter, producing format-aware STL geometry. They are two package paths in one source-level parser family. The standalone adapter supplies a no-op `Db.php` file for an unused legacy include, so it does not test either full application. Heratio's released `ahg/3d-model` Composer library uses `ModelMetadataExtractor::extract` to read PLY header element counts. This verifies a narrower parser scope than geometry loading. The Assimp wrapper is a distinct PHP package path that shares its underlying native parser with other ecosystem cells. Its later 0.6.0 release remains excluded after a failed control.

Packagist returned no package entries for Providence, Pawtucket2, or `ahg/3d-model` on the observation date. Their GitHub stars are recorded as auxiliary repository signals only. Other copied Providence `PlyToStl.php` files found in code search are not counted without an independently pinned release and control.

The bounded searches saved 927 hits with 843 unique identifiers across Packagist, GitHub repository search, GitHub code search, and Sourcegraph. Follow-up Packagist queries for Gmsh, VTK, 3D models, point clouds and PLY parsers surfaced no additional documented PHP PLY reader. The focused `element vertex` PHP code query returned 39 files, mostly CollectiveAccess copies or PLY writers; a `PlyToStl.php` filename query found 24 files, primarily copies of the same class. The tagged `resturahmania/pawtucket2` fork contains a byte-identical copy of the already-counted Pawtucket2 parser and is excluded as a duplicate package. `insta3D` has PLY-related PHP code and a tag but no open-source license for that code. API-name searches found no additional PHP reader: `PlyReader` largely matched unrelated `ReplyReader` names, `readPly` returned zero, and `parsePLY` was browser JavaScript embedded in a PHP page. Broad code queries were noisy; only their first 100 results were saved. These searches do not establish that no other PHP PLY parser exists. The PHP standard and bundled API inventory found no documented format-aware PLY parser within its stated scope. Evidence and limits are in `cell.json`, `supplementary-search.json`, `leads.json`, `source-lock.json`, `verification.json`, and `standard.json`.
