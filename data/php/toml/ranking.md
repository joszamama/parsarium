# PHP × TOML: selected parsers (pilot)

3 control-verified third-party paths selected. The ceiling is ten; this pilot does not pad the selection. A path is an API or package route, not necessarily an independent parser engine. PHP has no standard-library TOML API ([standard.json](standard.json)).

## Primary within-cell adoption metric

Packagist total downloads, from the bounded search captured 2026-11-17 ([snapshot](registry-snapshot.json)).

| Rank | Package | Release | Metric | Parsed scope | Parser family |

| 1 | [internal/toml](https://packagist.org/packages/internal/toml) | 1.1.3 | 325,891 | One TOML document via `Toml::parse(string)`; Document AST walked into the typed tree and checked against `Document::toArray()` | internal/toml Lexer, recursive-descent Parser and AST |

| 3 | [petalbranch/toml](https://packagist.org/packages/petalbranch/toml) | v1.2.0 | 20 | One TOML document via `Parser::parseToNode(string)` (the tree behind `Toml::parse`); node tree walked by `TomlType` into the typed tree and checked against `Toml::parse()` | petalbranch/toml Lexer, LazyTokenStream, Parser and node tree |

The three paths share no parser code (petalbranch/toml's normalized `src/` lines overlap the others by at most 9.7%, all generic accessors). No array API keeps every TOML scalar kind: internal/toml's `parseToArray()` returns local date-times and local dates as `DateTimeImmutable` values, just like offset date-times, and local times as strings, php-collective/toml's `decode()` returns all three local kinds as strings, and petalbranch/toml's `Toml::parse()` formats all four date-time kinds back to strings. Each harness therefore reads the kinds from the library's documented AST value nodes, places them where the library's own array assembly places their values, and requires the two to agree. Both valid controls ([service-config](../../../controls/toml/service-config.toml), [typed-scalars](../../../controls/toml/typed-scalars.toml)) match the hand-written typed trees exactly.

internal/toml: Xdebug covers 547 package lines on service-config and 608 on typed-scalars. The parser-line AFL++ bridge repeats identically three times on each control and differs by 255 lines and 255 tuples between them, mostly in `Lexer.php` and `Parser.php` ([receipt](internal-toml-feedback-differential.json)). php-collective/toml: Xdebug covers 825 and 780 package lines; the bridge differs by 477 lines and 475 tuples, in `Lexer.php`, `Parser.php`, `Normalizer.php` and the AST value classes ([receipt](php-collective-toml-feedback-differential.json)). petalbranch/toml: Xdebug covers 546 and 639 package lines; the bridge differs by 269 lines and 269 tuples, in `Lexer.php`, `Parser.php`, the node classes and the `Toml*` date-time support classes ([receipt](petalbranch-toml-feedback-differential.json)). Its 20 downloads are weak adoption evidence.

Unverified leads ([leads.json](leads.json)); every lead with a positive download count and a tagged release failed a valid control, so the cell stays at three: [yosymfony/toml](https://packagist.org/packages/yosymfony/toml) v1.0.4 (1,996,947 downloads) implements TOML 0.4.0, and its `Toml::parse` rejects typed-scalars with `Syntax error: unexpected token "T_UNQUOTED_KEY" at line 6 with value "xDEAD_BEEF"`, because that TOML version has no hexadecimal integers. [devium/toml](https://packagist.org/packages/devium/toml) 1.1.1 (134,459) matches service-config, but it returns typed-scalars' local time `00:32:00.25` as `TomlLocalTime` with `millisecond: 25`, which is 0.025 s. jamesmoss/toml 1.1.1 (31,882), leonelquinteros/php-toml v1.1.1 (7,863) and zidizei/toml-php 0.3.0 (121) are pre-0.4 parsers that reject inline tables or hexadecimal integers. app-hive/toml 0.0.2 (30) needs an undeclared ext-gmp and returns all date-times as plain strings. dayvsonspacca/psl-toml v1.0.5 (4) needs an undeclared ext-bcmath and returns -0.5 as 0 and local dates and times as full `DateTimeImmutable` values. checkdomain/php-toml (15), makhnanov/toml (3), azjezz/toml (1) and blixon/toml (0) have no tagged Packagist release, and cline/toml (0, a TOML 0.4 yosymfony fork) has no downloads; they were not run.
