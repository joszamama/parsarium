# C × JSON: selected parsers (pilot)

Nine verified third-party paths, ranked by one Debian metric. The ceiling is ten. The tenth slot stays open: no remaining lead with a positive Debian count passes the valid controls, and parson has no Debian source (stars are allowed only in PLY cells).

## Adoption metric

Debian popcon `sourcemax` installations by source package, captured 2026-11-17 from the pinned snapshot [`popcon-sourcemax-by_inst.gz`](../../curation/popcon-sourcemax-by_inst.gz) (SHA-256 `9d5e341c8ede7267acab176e255be83aca763f09901477eef5324d644cdaebf8`, source Last-Modified 2026-11-16). cJSON uses its documented `cJSON_ParseWithLengthOpts` local byte-buffer API. The [pinned source archive](https://github.com/DaveGamble/cJSON/releases/tag/v1.7.19) has SHA-256 `7fa616e3046edfa7a28a32d5f9eacfd23f92900fe1f8ccd988c1662f30454562` and an MIT LICENSE. Its Docker control traverses the parsed cJSON tree and compares the full nested JSON value to the valid object control. Two repeated valid controls produce identical parser-source LLVM regions and AFL++ bitmaps; the valid nested-array control changes 39 parser features and 29 AFL tuples ([receipt](afl-feedback.json)).

yyjson uses the documented `yyjson_read(dat, len, 0)` byte-buffer API. The [pinned release](https://github.com/ibireme/yyjson/releases/tag/0.13.0) source archive has SHA-256 `34e0f62a2bc11ab20d601e8ca1cc2b2079503aa45119a19133d89d19b94a0fae` and an MIT LICENSE. Its full parsed document matches each valid control; repeat feedback is stable, and the second control changes 473 parser regions and 408 AFL tuples.

JSON-GLib 1.10.8 comes from the [GNOME release tarball](https://download.gnome.org/sources/json-glib/1.10/json-glib-1.10.8.tar.xz), SHA-256 `55c5c141a564245b8f8fbe7698663c87a45a7333c2a2c56f06f811ab73b212dd` (LGPL-2.1-or-later), the same upstream version as Debian forky/sid. The harness calls the [documented](https://gnome.pages.gitlab.gnome.org/json-glib/method.Parser.load_from_data.html) `json_parser_load_from_data` with the exact byte length after `json_parser_set_strict(parser, TRUE)`. `json-parser.c` is JSON-GLib's own recursive-descent parser over its own `json-scanner.c` tokenizer; GLib provides only containers. Each valid control's JsonNode tree equals Python's `json.loads` result, including member order and int64/double kinds. The base control covers 1,176 JSON-GLib lines (438 in `json-parser.c`). The parser-only AFL++ probe instruments only the parser, scanner and node/object/array/value sources (checked with `nm`); three runs per control repeat exactly and the controls differ by 22 of 304/298 tuples and 34 source lines ([receipt](../../../fuzzing/afl-native/json/c/json-glib/differential.json)).

jq 1.8.2 comes from the [official release asset](https://github.com/jqlang/jq/releases/tag/jq-1.8.2), SHA-256 `71b8d6e8f5fe81f6c6d0d110e3892251f6ce76ed095abd315e26e6e1193af3af` (MIT; bundled decNumber under the ICU license). Debian forky/sid ship 1.8.2. The harness links libjq (built without oniguruma) and calls `jv_parse_sized(bytes, length)`. That C API is documented on jq's [project wiki](https://github.com/jqlang/jq/wiki/C-API:-jv), which calls the jv API public "mostly" without a stability commitment; the jq manual covers only the program, and the pinned `src/jv.h` declares the function. jq's own `jv_dump_string` prints the tree in object insertion order; jq has a single number kind, so the integer/float distinction checked against `json.loads` comes from jq's preserved decimal literal. The harness and probe define `arc4random()` to fix jq's per-process object hash seed, which jq does not let callers set; without it repeated AFL++ maps differed. The base control covers 1,139 libjq lines (356 in `jv_parse.c`). The parser-only probe instruments `jv_parse.c`, `jv.c`, `jv_unicode.c`, `jv_alloc.c` and `jv_dtoa.c`; three runs per control repeat exactly and the controls differ by 26 of 219/203 tuples and 44 source lines ([receipt](../../../fuzzing/afl-native/json/c/jq/differential.json)). The 141,218 count belongs to the `jq` source package, mostly the command-line program and its libjq1 dependency, not libjq API use.

libfastjson 1.2609.0 comes from the [rsyslog release download](https://download.rsyslog.com/libfastjson/libfastjson-1.2609.0.tar.gz) for tag v1.2609.0, SHA-256 `7cd6f78c1c07f4140f6976a9a0e0048bcaa7292329c6ac2c0e070383d83d8edd` (MIT). Debian forky/sid ship this version; trixie ships 1.2304.0. It is rsyslog's fork of json-c and shares the json-c tokener family with the json-c row; PROTOCOL.md allows a shared family as a separate package path when it is recorded. The harness calls the [documented](https://github.com/rsyslog/libfastjson/blob/v1.2609.0/json_tokener.h) `fjson_tokener_parse_ex` in `FJSON_TOKENER_STRICT` mode on the exact length and rejects non-whitespace after `tok->char_offset`. Its fjson_object tree matches each valid control with key order and int/double kinds. libfastjson documents that it does not support NUL inside strings. The base control covers 729 library lines (362 in `json_tokener.c`). The parser-only probe instruments `json_tokener.c`, `json_object.c`, `arraylist.c` and `printbuf.c`; three runs per control repeat exactly and the controls differ by 21 of 220/203 tuples and 15 source lines ([receipt](../../../fuzzing/afl-native/json/c/libfastjson/differential.json)).

json-parser 1.1.0 (Debian source `libjsonparser`, same version) is pinned from its [release tag](https://github.com/json-parser/json-parser/releases/tag/v1.1.0) archive, SHA-256 `5c278793269dbbf98d5f1592c797234581df69088d2838a14154b4af52ebd133` (BSD-2-Clause). The harness calls the [documented](https://github.com/json-parser/json-parser/blob/v1.1.0/README.md) `json_parse_ex(settings, bytes, length, error)` with default settings. Its json_value tree keeps member order and separate `json_integer`/`json_double` kinds and equals `json.loads` for both controls. The base control covers 446 lines of its single `json.c`. The parser-only probe instruments only `json.c`; three runs per control repeat exactly and the controls differ by 15 of 113/108 tuples and 30 source lines ([receipt](../../../fuzzing/afl-native/json/c/json-parser/differential.json)). Its rank rests on 844 Debian installations.

yajl 2.1.0 (Debian source `yajl`, same version; the last upstream release, from 2014) is pinned from its [release tag](https://github.com/lloyd/yajl/releases/tag/2.1.0) archive, SHA-256 `3fb73364a5a30efe615046d07e6db9d09fd2b41c763c5f7d3bfb121cd5c5ac5a` (ISC). The harness uses the event API [documented](https://github.com/lloyd/yajl/blob/2.1.0/src/api/yajl_parse.h) in the public `yajl_parse.h`: `yajl_alloc` with a callback table, `yajl_parse(handle, bytes, length)` and `yajl_complete_parse`, with the default configuration (no comments, trailing garbage or multiple values). yajl's own lexer separates integer and double tokens and calls `yajl_integer` or `yajl_double`; the callbacks only print events in arrival order, so the printed tree keeps member order and number kinds and equals `json.loads` for both controls. The `yajl_tree` convenience layer, which turns comments on, is not used. The base control covers 575 yajl lines (214 in `yajl_parser.c`). The parser-only probe uses no-op callbacks and instruments only the lexer, parser, encoder, buffer and allocator sources (checked with `nm`). It uses AFL++ CLASSIC instrumentation with a pinned 65,536-entry map: the default PCGUARD build crashed in `yajl_do_parse` on both valid controls on arm64, while the coverage, sanitizer and CLASSIC builds parse them. Three runs per control repeat exactly and the controls differ by 34 of 329/307 tuples and 24 source lines ([receipt](../../../fuzzing/afl-native/json/c/yajl/differential.json)). yajl was missed by the `json` source-name search because its source name lacks `json`; it was found by the tenth-slot exact source-name lookups recorded in the [snapshot](registry-snapshot.json).

## Unresolved leads

| Lead | Popcon installations | Status |
| --- | ---: | --- |
| [parson](https://github.com/kgabis/parson) | unavailable | Verified technically; no Debian source package |
| [frozen](https://github.com/cesanta/frozen) | 16 | Fails the nested-object control |
| [jsmn](https://github.com/zserge/jsmn) | 11 | Tokenizer only; not eligible for the value gate |
| [liblaxjson](https://github.com/andrewrk/liblaxjson) | 1 | Fails the nested-object control; numbers only as doubles ([evidence](liblaxjson-lead-check.json)) |

frozen 1.7's `json_walk` types tokens but leaves values as raw spans; its `json_unescape` turns the control's `\u00e9` into the single byte 0xE9 rather than UTF-8, so the nested-object control cannot match. liblaxjson 1.0.5 (MIT, archive SHA-256 `ffc495b5…`) rejects the nested-object control at `-0.25e1`, because its exponent state requires an explicit `+` or `-`, and delivers every number through a single `atof()` double callback, so integer/float kinds cannot be observed. jsmn reports only object/array/string/primitive token spans without decoding strings or typing primitives, so the harness would have to interpret JSON itself. parson 1.5.4 passed both controls, 530 own lines and 34 stable AFL++ tuple differences in candidate commit 271447a6, but has no Debian source package and so no primary value; stars are not an allowed fallback outside PLY cells.

## Search

Conan Center search: recipe-name substring `json` (24 hits) plus `jansson`, `jsmn`, `parson` targeted names (3 hits), at most 100 results per query; 27 recorded hits, 27 unique. That surface missed Debian-packaged C parsers, so the same hashed popcon snapshot was searched on 2026-11-17 for Debian source names containing `json`: 320 hits, 320 unique, all recorded and classified in the [snapshot](registry-snapshot.json). C JSON parser libraries among them are json-c, JSON-GLib, cJSON, libfastjson, yyjson, libjsonparser and liblaxjson; jsonrpc-glib, lua-cjson, tree-sitter-json, wal2json, lz4json and gjh-asl-json are C code but not separate JSON value libraries, and the rest are other languages, tools or C++ (picojson belongs to the C++ cell). Exact source-name lookups in the same file add jansson, jq (141,218), frozen (16) and jsmn (11); parson has no Debian source. A second exact-lookup pass on 2026-11-17 added yajl (152,183, selected) and decided ten other names: mongo-c-driver (libbson's JSON reader in a multi-library source), libwebsockets, systemd, ell and libfyaml (JSON is one module or a YAML subset, so the counts are not JSON-specific), `ucl` (the UCL compression library, not the libucl configuration parser), and cjose, jshon and jsonrpc-glib (built on jansson or JSON-GLib); wjelement, jsonsl, nxjson, mjson, ccan, libucl, tiny-json, microjson, sajson and json11 have no Debian source in the snapshot. The pinned releases and valid controls support only the observed JSON subset; a complete RFC 8259 implementation claim would need more evidence.

Round 4 (2026-11-18): Debian apt-cache search, vcpkg/Homebrew/Conan lists and a GitHub C search found no further C JSON value library with a Debian source; the tenth slot stays open ([snapshot](registry-snapshot.json), `round_4_discovery`).
