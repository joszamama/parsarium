**github.com/miekg/dns v1.1.73** (BSD-3-Clause) parses local bytes with `(*dns.Msg).Unpack(msg []byte) error`. Both controls match the oracle summary. The response control covers 207 library lines in 10 files. AFL++ feedback repeats 3 times per control; response and query give 131/73 parser features and 150/92 AFL++ tuples, differing by 60 features and 60 tuples ([receipt](github-com-miekg-dns-feedback-differential.json)). Own pure-Go decoder; CoreDNS and many Go DNS tools build on it. codeberg.org/miekg/dns is a later v2 rewrite by the same author.

**github.com/google/gopacket/layers v1.1.19** (BSD-3-Clause) parses local bytes with `(*layers.DNS).DecodeFromBytes(data []byte, df gopacket.DecodeFeedback) error`. Both controls match the oracle summary. The response control covers 282 library lines in 3 files. AFL++ feedback repeats 3 times per control; response and query give 86/67 parser features and 105/87 AFL++ tuples, differing by 19 features and 18 tuples ([receipt](github-com-google-gopacket-layers-feedback-differential.json)). Own pure-Go decoder inside Google's packet-decoding library; no libpcap is used (the pcap subpackage is not imported). It keeps the 3-bit Z field. Its importer count covers the whole multi-protocol layers package. github.com/gopacket/gopacket is a community fork of the same code.

**golang.org/x/net/dns/dnsmessage v0.63.0** (BSD-3-Clause) parses local bytes with `(*dnsmessage.Message).Unpack(msg []byte) error`. Both controls match the oracle summary. The response control covers 203 library lines in 1 file. AFL++ feedback repeats 3 times per control; response and query give 115/78 parser features and 135/98 AFL++ tuples, differing by 37 features and 37 tuples ([receipt](golang-org-x-net-dns-dnsmessage-feedback-differential.json)). Own pure-Go decoder maintained by the Go team; the standard library's net resolver vendors a copy of the same package internally (vendor/golang.org/x/net/dns/dnsmessage), which exports no API, so the cell has no standard path. dnsmessage keeps AD and CD but not the reserved Z bit, so z reports AD and CD only. A and AAAA bodies are fixed byte arrays; the harness prints them with net/netip. Its importer count is for this package only.

**codeberg.org/miekg/dns v0.6.133** (BSD-3-Clause) parses local bytes with `(*dns.Msg).Unpack() error`. Both controls match the oracle summary. The response control covers 154 library lines in 9 files. AFL++ feedback repeats 3 times per control; response and query give 104/47 parser features and 123/67 AFL++ tuples, differing by 57 features and 56 tuples ([receipt](codeberg-org-miekg-dns-feedback-differential.json)). Same author as the selected github.com/miekg/dns v1 but a separate module and a rewrite, not a rename: only 1,699 of the 7,165 distinct non-test source lines of its root package (23.7%) also occur in v1.1.73's root package, and the decoder moved to internal/unpack and pkg/dnsnet with rdata in its own package. Shared family with miekg/dns v1 is stated; the API differs (the caller puts the bytes in Msg.Data before Unpack, questions are RRs). It keeps the Z, AD and CD bits. Its importer count is low because it is pre-1.0 (v0.6.x).

**github.com/benburkert/dns v0.0.0-20190225204957-d356cf78cdfc** (MIT) parses local bytes with `(*dns.Message).Unpack(b []byte) ([]byte, error)`. Both controls match the oracle summary. The response control covers 115 library lines in 2 files. AFL++ feedback repeats 3 times per control; response and query give 77/36 parser features and 97/56 AFL++ tuples, differing by 41 features and 41 tuples ([receipt](github-com-benburkert-dns-feedback-differential.json)). Own pure-Go decoder with its own name decompressor; no code from miekg/dns or x/net. The module has no tagged release, so the pinned version is the pseudo-version of the last commit (2019-02-25). It drops the Z, AD and CD bits, so z is reported as 0. TTLs are stored as time.Duration and printed in whole seconds.

**github.com/phuslu/fastdns v0.17.2** (MIT) parses local bytes with `fastdns.ParseMessage(dst *Message, payload []byte, copying bool) error; (*Message).Records() and (*Message).DecodeName(dst, name []byte)`. Both controls match the oracle summary. The response control covers 100 library lines in 4 files. AFL++ feedback repeats 3 times per control; response and query give 63/37 parser features and 83/57 AFL++ tuples, differing by 26 features and 26 tuples ([receipt](github-com-phuslu-fastdns-feedback-differential.json)). Own zero-allocation decoder written for a DNS server; no code from miekg/dns or x/net. ParseMessage decodes the header and the single question (it rejects QDCOUNT other than 1) and keeps the 3-bit Z field; Records iterates owner name, type, class, TTL and raw RDATA over all record sections in wire order, and DecodeName follows compression pointers. Harness-side formatting: the harness splits records into sections by the parsed header counts, prints A/AAAA RDATA bytes with net/netip, and reads the 16-bit MX preference from the RDATA slice before decoding the exchange name with DecodeName.

**github.com/cznic/dns/msg v0.0.0-20181122101858-8a2913d6a50b** (BSD-3-Clause) parses local bytes with `(*msg.Message).Decode(b []byte, pos *int, sniffer dns.WireDecodeSniffer) error`. Both controls match the oracle summary. The response control covers 185 library lines in 3 files. AFL++ feedback repeats 3 times per control; response and query give 113/65 parser features and 133/85 AFL++ tuples, differing by 48 features and 48 tuples ([receipt](github-com-cznic-dns-msg-feedback-differential.json)). Own pure-Go decoder by Jan Mercl, written at CZ.NIC; no code from miekg/dns or x/net. The module has no tagged release (archived, pre-modules), so the pinned version is the pseudo-version of its last commit (2018-11-22). The harness passes position 0 and a nil decode sniffer. It keeps the Z, AD and CD bits. msg's package init starts an ID-generator goroutine whose first reseed raced process exit, which made two coverage blocks of msg/message.go vary between identical runs; the harness sleeps 50 ms once at start-up so that reseed always completes (parsing unchanged).

**tangled.sh/seiso.moe/magna v0.0.2** (MIT) parses local bytes with `(*magna.Message).Decode(buf []byte) error`. Both controls match the oracle summary. The response control covers 148 library lines in 6 files. AFL++ feedback repeats 3 times per control; response and query give 84/47 parser features and 104/67 AFL++ tuples, differing by 37 features and 37 tuples ([receipt](tangled-sh-seiso-moe-magna-feedback-differential.json)). Own pure-Go decoder (a small library behind a hobby DNS server); no code from miekg/dns or x/net. It keeps the 3-bit Z field. magna 0.0.2 has no AAAA type: type-28 RDATA is kept as magna.Reserved raw bytes, which the harness prints with net/netip (harness-side formatting, disclosed). ## Remaining leads

| Order | Lead | Metric | Status | Input API lead | Family |
| ---: | --- | ---: | --- | --- | --- |
| 1 | www.bamsoftware.com/git/dnstt.git/dns | 17 | unresolved_control_failure | `dns.MessageFromWireFormat([]byte)` | dnstt dns package |
| 2 | github.com/cybergarage/go-mdns/mdns/dns | 1 | unresolved_control_failure | `dns.NewMessageWithBytes([]byte)` | go-mdns dns package |

- **www.bamsoftware.com/git/dnstt.git/dns**: MessageFromWireFormat decodes the header, questions and record owner names, but every record keeps its RDATA as raw bytes (RR.Data) and the package exports no decoder for names inside RDATA (only DecodeRDataTXT). The control's compressed CNAME and MX targets could only be produced by the harness parsing RDATA itself, so the observed result would not come from the library.
- **github.com/cybergarage/go-mdns/mdns/dns**: The mDNS message parser has typed records only for PTR, SRV, TXT, A, AAAA and NSEC (mdns/dns/record_impl.go); CNAME and MX RDATA are left as untyped bytes, so the control's CNAME and MX answers cannot be reported from the library's parse.
