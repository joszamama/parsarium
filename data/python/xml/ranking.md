# Python × XML: pilot ranking

Nine third-party paths are control-verified, alongside one separately recorded standard API. Two of nine targeted documentation leads remain unverified. The ten-path ceiling is not a quota; this is not an exhaustive most-used ranking.

The within-cell adoption signal is [PyPI Stats](https://pypistats.org/api/) `last_month` downloads excluding known mirrors, observed 2026-11-17. It is a package-level proxy, including transitive and non-XML use. Only verified third-party paths appear below.

xmlschema is not an independent XML parser either: `XMLResource` consumes CPython's default `ElementTree.iterparse` events over the C `_elementtree` parser, pyexpat and the same Expat 2.10.0 build. It keeps namespace information of its own, a per-element namespace map and each element's xmlns declarations, so its controls match the lxml path's full summary including the declaration count. Its downloads are mostly XSD validation use and do not measure XML parsing.

The verified `xml.etree.ElementTree` standard API is [listed separately](standard.json). lxml and xmltodict use different underlying XML parser engines. beautifulsoup4 is not an independent XML parser: its documented `"xml"` builder feeds the bytes to lxml.etree.XMLParser (with `recover=True`) over the same libxml2 2.15.4 build, so it shares the lxml/libxml2 family. Most Beautiful Soup downloads are HTML use; its figure does not measure XML parsing. untangle is not an independent XML parser either: it handles SAX events from defusedxml's DefusedExpatParser over CPython's Expat driver, the same Expat 2.10.0 build as xmltodict. It parses with namespace processing off and drops namespace URIs, so its controls are compared with an lxml oracle projected to untangle's qualified-name view. defusedxml is not an independent XML parser: `defusedxml.ElementTree.parse` runs CPython's pure-Python ElementTree `XMLParser` over pyexpat and the same Expat 2.10.0 build, adding only entity-declaration and external-reference guard handlers (the DOCTYPE guard is off by default) that these DOCTYPE-free controls never trigger. ElementTree keeps no xmlns declarations, so its lxml-oracle comparison omits the declaration count. Its downloads are largely transitive and do not measure XML parsing.

lxml's, beautifulsoup4's and parsel's source coverage includes libxml2 `parser.c` lines 8700–8720. Their AFL++ feedback bridges exclude that line range because an address-sensitive attribute lookup varied across identical valid replays; the five-repeat control check was stable after that exclusion.

Parsel is not an independent XML parser either. Its documented [`Selector(body=bytes, type="xml")`](https://parsel.readthedocs.io/en/v1.12.1/parsel.html) strips the body and NUL bytes and calls `lxml.etree.fromstring` with `SafeXMLParser(recover=True, resolve_entities=False, huge_tree=True)`, an `lxml.etree.XMLParser` subclass, over the same lxml 6.1.3 and libxml2 2.15.4 pins, so it shares the lxml/libxml2 family with lxml and beautifulsoup4. The harness reads the tree only through `Selector.xpath()`, `get()` and `Selector.attrib`. Both valid controls match an independent CPython pyexpat (Expat 2.7.4) oracle and the beautifulsoup4 path's summary. The first control executes 100 Parsel `selector.py` lines and 1,484 libxml2 `parser.c` lines. Parsel's own lines are the same on both controls, so all of its input-dependent AFL++ feedback (213 features, 209 tuples, stable over five repeats) comes from libxml2 `parser.c`; this is shared-parser feedback, labeled as such ([feedback receipt](parsel-valid-feedback.json)). Most Parsel downloads come through Scrapy's HTML scraping and do not measure XML parsing. CDATA boundaries and the XML declaration are not kept.

pyquery is not an independent XML parser either. Its documented `PyQuery(bytes, parser="xml")` maps to `lxml.etree.fromstring` with lxml's default XMLParser over the same lxml 6.1.3 / libxml2 2.15.4 pins; pyquery wraps the returned lxml elements in a jQuery-style list. The harness walks the tree with `PyQuery.contents()` and reads the returned elements' names, attributes and in-scope namespaces. Both valid controls match an independent CPython pyexpat oracle for the keys pyquery reports (it returns no comments or processing instructions). The first control executes 48 pyquery lines and 1,475 libxml2 `parser.c` lines. pyquery's own lines are the same on both controls, so all of its input-dependent AFL++ feedback (213 features, 209 tuples, stable over five repeats) comes from libxml2 `parser.c`, the Parsel precedent, labelled as shared-parser feedback ([feedback receipt](pyquery-valid-feedback.json)). Most pyquery downloads are HTML scraping use.

jxmlease is not an independent XML parser either: `jxmlease.parse` creates a CPython pyexpat parser itself with namespace processing off and builds `XMLDictNode`/`XMLListNode`/`XMLCDATANode` objects from Expat events over the same Expat 2.10.0 build as xmltodict and untangle. It is a raw-name path: names are reported as written (`c:catalog`, `c:lang`, `p:amount`) and xmlns declarations stay attributes, so its summary is compared with the expat non-namespace oracle used for the C raw-name paths and with an lxml/libxml2 parse projected to raw names, not with expanded names. The first control executes 239 jxmlease lines and 2,197 Expat lines. Its own lines are the same on both controls; all input-dependent AFL++ feedback (794 features, 757 tuples, stable over five repeats) comes from Expat ([feedback receipt](jxmlease-valid-feedback.json)). Same-name siblings are grouped into lists, so order across differently named siblings is not kept.
