# Python × XML: pilot ranking

The within-cell adoption signal is [PyPI Stats](https://pypistats.org/api/) `last_month` downloads excluding known mirrors, observed 2026-11-17. It is a package-level proxy, including transitive and non-XML use. Only verified third-party paths appear below.

The verified `xml.etree.ElementTree` standard API is [listed separately](standard.json). lxml and xmltodict use different underlying XML parser engines. beautifulsoup4 is not an independent XML parser: its documented `"xml"` builder feeds the bytes to lxml.etree.XMLParser (with `recover=True`) over the same libxml2 2.15.4 build, so it shares the lxml/libxml2 family. Most Beautiful Soup downloads are HTML use; its figure does not measure XML parsing. untangle is not an independent XML parser either: it handles SAX events from defusedxml's DefusedExpatParser over CPython's Expat driver, the same Expat 2.10.0 build as xmltodict. It parses with namespace processing off and drops namespace URIs, so its controls are compared with an lxml oracle projected to untangle's qualified-name view. defusedxml is not an independent XML parser: `defusedxml.ElementTree.parse` runs CPython's pure-Python ElementTree `XMLParser` over pyexpat and the same Expat 2.10.0 build, adding only entity-declaration and external-reference guard handlers (the DOCTYPE guard is off by default) that these DOCTYPE-free controls never trigger. ElementTree keeps no xmlns declarations, so its lxml-oracle comparison omits the declaration count. Its downloads are largely transitive and do not measure XML parsing.

lxml's and beautifulsoup4's source coverage includes libxml2 `parser.c` lines 8700–8720. Their AFL++ feedback bridges exclude that line range because an address-sensitive attribute lookup varied across identical valid replays; the five-repeat control check was stable after that exclusion.
