# Python × TOML: pilot ranking

Four third-party paths are control verified. This is a bounded pilot cell, not a claim about the most-used TOML parsers. The leads came from targeted PyPI and PyPI Stats lookups beside one bounded [PyPI Simple index name search](registry-snapshot.json) (first 100 alphabetical hits of 409), because that index has no relevance order.

The within-cell metric is [PyPI Stats](https://pypistats.org/api/) `last_month` package downloads excluding known mirrors, captured 2026-11-17 in the [registry snapshot](registry-snapshot.json). It counts whole-package installs, including transitive installs and uses unrelated to parsing.

| Rank | Package | Release | Metric | Parsed scope | Parser family |

| 1 | [tomlkit](https://github.com/python-poetry/tomlkit/blob/0.15.2/docs/api.rst) | 0.15.2 | 591,365,129 | TOML 1.0.0 document from local text via `tomlkit.parse`, walked by tomlkit item type with each scalar unwrapped | tomlkit pure-Python style-preserving recursive-descent parser (`parser.py` over `source.py`) |

All four paths give the exact hand-written typed tree of both controls ([service-config](../../../controls/toml/service-config.toml) and [typed-scalars](../../../controls/toml/typed-scalars.toml)) on every API mode tried, and CPython `tomllib` in the same image gives the same trees. The [tomlkit receipt](tomlkit-valid-feedback.json) covers 845 package lines on the primary control (408 in `parser.py`); three runs per control give identical feedback, and the controls differ by 404 source lines and 401 AFL++ tuples. tomlkit keeps comments and formatting in its items; only parsed values are compared. Its downloads mostly reflect Poetry and other build tools. The [tomli receipt](tomli-valid-feedback.json) covers 284 lines (259 in `_parser.py`, 25 in `_re.py`); the controls differ by 137 source lines and 137 AFL++ tuples. CPython's `tomllib` is a vendored copy of tomli, so tomli and the [standard API](standard.json) are one family, not independent parsers; the hand-written trees are tomli's independent check. Only tomli's pure-Python wheel is measured, not the mypyc-compiled wheels that pip prefers where they exist. tomlkit and tomli are independent code bases. The [rtoml receipt](rtoml-valid-feedback.json) measures a source build of the pinned sdist with Rust LLVM coverage (the official wheel is not instrumented): 768 lines of the toml_parser 1.1.5 lexer and parser (181 in `parser/document.rs`) and 488 underlying lines of the toml 1.1.8 crate on the primary control; three runs per control give identical LLVM region feedback, and the controls differ by 1,302 region features and 1,242 AFL++ tuples over the toml, toml_parser and toml_datetime sources. rtoml is a PyO3 wrapper; its lexer and parser are the same toml_parser 1.1.5 release as the selected Rust `toml` and `toml_edit` paths, so it is a shared-family path, independent of tomli and tomlkit. The [pytomlpp receipt](pytomlpp-valid-feedback.json) measures a clang source build of the pinned sdist on linux/arm64 (PyPI has no aarch64 wheel): 922 lines of the vendored toml++ headers (729 in `impl/parser.inl`); three runs per control give identical feedback, and the controls differ by 735 region features (633 in `parser.inl`) and 715 AFL++ tuples. pytomlpp is a pybind11 wrapper over a toml++ submodule snapshot taken after the v3.4.0 tag (26 changed lines of 3,917 in `parser.inl`), so it shares the toml++ family with the selected C++ path.

Unverified leads ([leads.json](leads.json)): toml 0.10.2 (145,147,540) fails the typed-scalars control, because `toml.loads` returns `datetime.time(0, 32)` for the local time `00:32:00.25` and drops its fractional seconds; the service-config control matches. toml-rs 0.4.3 (18,062; PyO3 over a Rust parser taken from the lava-sh/toml git branch `for_python_toml_rs`) gives both exact typed trees but stays a lead: its parser source is an unreleased git branch rather than a crates.io release, and its relation to the toml-rs family is not established. pytoml 0.1.21 (337,081) rejects the hexadecimal integer of typed-scalars, and qtoml 0.3.1 (2,002) rejects its offset date-time with fractional seconds; both match service-config. tomli-w (85,996,374) is excluded as a writer.
