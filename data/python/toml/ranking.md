# Python × TOML: pilot ranking

Seven third-party paths are control verified. This is a bounded pilot cell, not a claim about the most-used TOML parsers. The leads came from targeted PyPI and PyPI Stats lookups beside one bounded [PyPI Simple index name search](registry-snapshot.json) (first 100 alphabetical hits of 409), because that index has no relevance order.

The within-cell metric is [PyPI Stats](https://pypistats.org/api/) `last_month` package downloads excluding known mirrors, captured 2026-11-17 in the [registry snapshot](registry-snapshot.json). It counts whole-package installs, including transitive installs and uses unrelated to parsing.

All seven paths give the exact hand-written typed tree of both controls ([service-config](../../../controls/toml/service-config.toml) and [typed-scalars](../../../controls/toml/typed-scalars.toml)) on every API mode tried, and CPython `tomllib` in the same image gives the same trees. The [tomlkit receipt](tomlkit-valid-feedback.json) covers 845 package lines on the primary control (408 in `parser.py`); three runs per control give identical feedback, and the controls differ by 404 source lines and 401 AFL++ tuples. tomlkit keeps comments and formatting in its items; only parsed values are compared. Its downloads mostly reflect Poetry and other build tools. The [tomli receipt](tomli-valid-feedback.json) covers 284 lines (259 in `_parser.py`, 25 in `_re.py`); the controls differ by 137 source lines and 137 AFL++ tuples. CPython's `tomllib` is a vendored copy of tomli, so tomli and the [standard API](standard.json) are one family, not independent parsers; the hand-written trees are tomli's independent check. Only tomli's pure-Python wheel is measured, not the mypyc-compiled wheels that pip prefers where they exist. tomlkit and tomli are independent code bases. The [rtoml receipt](rtoml-valid-feedback.json) measures a source build of the pinned sdist with Rust LLVM coverage (the official wheel is not instrumented): 768 lines of the toml_parser 1.1.5 lexer and parser (181 in `parser/document.rs`) and 488 underlying lines of the toml 1.1.8 crate on the primary control; three runs per control give identical LLVM region feedback, and the controls differ by 1,302 region features and 1,242 AFL++ tuples over the toml, toml_parser and toml_datetime sources. rtoml is a PyO3 wrapper; its lexer and parser are the same toml_parser 1.1.5 release as the selected Rust `toml` and `toml_edit` paths, so it is a shared-family path, independent of tomli and tomlkit. The [pytomlpp receipt](pytomlpp-valid-feedback.json) measures a clang source build of the pinned sdist on linux/arm64 (PyPI has no aarch64 wheel): 922 lines of the vendored toml++ headers (729 in `impl/parser.inl`); three runs per control give identical feedback, and the controls differ by 735 region features (633 in `parser.inl`) and 715 AFL++ tuples. pytomlpp is a pybind11 wrapper over a toml++ submodule snapshot taken after the v3.4.0 tag (26 changed lines of 3,917 in `parser.inl`), so it shares the toml++ family with the selected C++ path.

**tomlrt 2.3.3** (MIT). tomlrt (dimbleby) scans and parses TOML with its own tomlrt/_scanner.py, tomlrt/_parser.py and tomlrt/_scalar.py into format-preserving Document/Table/Array views that subclass dict and list and hold plain Python scalars. A line comparison of the pinned sources finds under 1.2% shared non-trivial lines with tomlkit 0.15.2 or tomli 2.5.0, so it is an independent family; CPython tomllib (tomli family) is an independent cross-check. Found through the toml-lang/toml wiki TOML 1.1 implementation list. Python line tracing covers 739 package lines on service-config (172 in `_parser.py`); the [feedback receipt](tomlrt-valid-feedback.json) records 751 and 672 AFL++ tuples, 333 differing, with three identical runs per control. Metric: PyPI Stats 519,376, a targeted lookup on 2026-11-18 (`round_4_targeted_lookups`).

**tomlclass 0.4.1** (MIT). tomlclass (wsu2059q) parses with its own tomlclass/parser.py into a lossless node tree (tomlclass/nodes.py, tomlclass/_document.py); loads() converts that Document to a tomllib-compatible plain dict. Under 1.3% of its non-trivial source lines also occur in tomlkit, tomli or tomlrt, so it is an independent family. Found through the toml-lang/toml wiki TOML 1.1 implementation list. Python line tracing covers 402 package lines on service-config (323 in `parser.py`); the [feedback receipt](tomlclass-valid-feedback.json) records 422 and 445 AFL++ tuples, 267 differing, with three identical runs per control. Metric: PyPI Stats 2,652, a targeted lookup on 2026-11-18 (`round_4_targeted_lookups`).

**pytoml11 0.0.5** (MIT). toml11 (ToruNiina/toml11), C++: pytoml11's pybind11 _value.loads calls toml::parse_str<toml::ordered_type_config> from the single-header toml11 4.2.0 vendored in the sdist (src/toml.hpp) and wraps the toml11 value in its own Item classes. Same parser family as the selected C++ toml11 4.4.0 path (two minor releases older); independent of tomli/tomllib, tomlkit, tomlrt, tomlclass, the Rust toml_parser family of rtoml and the toml++ family of pytomlpp. A shared-family wrapper whose differential is in the underlying toml11 parser; found through the toml-lang/toml wiki TOML 1.0 list (binding of toml11). LLVM region coverage of a clang 16 source build covers 821 toml11 header lines on service-config (821 in `toml.hpp`); the [feedback receipt](pytoml11-valid-feedback.json) records 1,459 and 1,549 AFL++ tuples, 600 differing, with three identical runs per control. Metric: PyPI Stats 200, a targeted lookup on 2026-11-18 (`round_4_targeted_lookups`).

Unverified leads ([leads.json](leads.json)): toml 0.10.2 (145,147,540) fails the typed-scalars control, because `toml.loads` returns `datetime.time(0, 32)` for the local time `00:32:00.25` and drops its fractional seconds; the service-config control matches. toml-rs 0.4.3 (18,062) gives both exact typed trees but is excluded as a fork: it builds toml, toml_parser and toml_edit from lava-sh/toml git forks of toml-rs/toml, whose `toml_parser` sources share 94.1% (TOML 1.0 rev `b1581597`) and 97.3% (TOML 1.1 rev `b3ab4b9d`) of their lines with crates.io toml_parser 1.1.5, the family already selected here through rtoml. pytoml 0.1.21 (337,081) rejects the hexadecimal integer of typed-scalars, and qtoml 0.3.1 (2,002) rejects its offset date-time with fractional seconds; both match service-config. tomli-w (85,996,374) is excluded as a writer. From the targeted lookups: toml.py 0.1.7, toml-python 0.4.1 and contoml 0.32 fail the controls (TOML 0.x grammars or Python 2 code), libtoml 1.0 has no arrays of tables, and fasttoml publishes only pre-releases; dom-toml delegates to the standard tomllib, and tomli-rs, rustoml, spanned-toml, tomli-null and toml-tools are wrappers or forks of selected families.
