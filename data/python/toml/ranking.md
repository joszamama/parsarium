# Python × TOML: pilot ranking

Three third-party paths are control verified. This is a bounded pilot cell, not a claim about the most-used TOML parsers. The leads came from targeted PyPI and PyPI Stats lookups beside one bounded [PyPI Simple index name search](registry-snapshot.json) (first 100 alphabetical hits of 409), because that index has no relevance order.

The within-cell metric is [PyPI Stats](https://pypistats.org/api/) `last_month` package downloads excluding known mirrors, captured 2026-11-17 in the [registry snapshot](registry-snapshot.json). It counts whole-package installs, including transitive installs and uses unrelated to parsing.

| Rank | Package | Release | Metric | Parsed scope | Parser family |
| ---: | --- | --- | ---: | --- | --- |
| 1 | [tomlkit](https://github.com/python-poetry/tomlkit/blob/0.15.2/docs/api.rst) | 0.15.2 | 591,365,129 | TOML 1.0.0 document from local text via `tomlkit.parse`, walked by tomlkit item type with each scalar unwrapped | tomlkit pure-Python style-preserving recursive-descent parser (`parser.py` over `source.py`) |
| 2 | [tomli](https://github.com/hukkin/tomli/blob/2.5.0/README.md) | 2.5.0 | 263,305,223 | TOML 1.0.0 document from local text via `tomli.loads` (plain dict) | tomli pure-Python parser (`_parser.py`, `_re.py`); same family as the standard `tomllib` |
| 3 | [rtoml](https://github.com/samuelcolvin/rtoml/blob/v0.14/README.md) | 0.14.0 | 1,380,894 | TOML 1.0.0 document from local text via `rtoml.loads` (plain dict built by the PyO3 extension) | Rust toml_parser family: toml 1.1.8 `Deserializer` over toml_parser 1.1.5, shared with the Rust `toml` and `toml_edit` paths |

Both paths give the exact hand-written typed tree of both controls ([service-config](../../../controls/toml/service-config.toml) and [typed-scalars](../../../controls/toml/typed-scalars.toml)) on every API mode tried, and CPython `tomllib` in the same image gives the same trees. The [tomlkit receipt](tomlkit-valid-feedback.json) covers 845 package lines on the primary control (408 in `parser.py`); three runs per control give identical feedback, and the controls differ by 404 source lines and 401 AFL++ tuples. tomlkit keeps comments and formatting in its items; only parsed values are compared. Its downloads mostly reflect Poetry and other build tools. The [tomli receipt](tomli-valid-feedback.json) covers 284 lines (259 in `_parser.py`, 25 in `_re.py`); the controls differ by 137 source lines and 137 AFL++ tuples. CPython's `tomllib` is a vendored copy of tomli, so tomli and the [standard API](standard.json) are one family, not independent parsers; the hand-written trees are tomli's independent check. Only tomli's pure-Python wheel is measured, not the mypyc-compiled wheels that pip prefers where they exist. tomlkit and tomli are independent code bases. The [rtoml receipt](rtoml-valid-feedback.json) measures a source build of the pinned sdist with Rust LLVM coverage (the official wheel is not instrumented): 768 lines of the toml_parser 1.1.5 lexer and parser (181 in `parser/document.rs`) and 488 underlying lines of the toml 1.1.8 crate on the primary control; three runs per control give identical LLVM region feedback, and the controls differ by 1,302 region features and 1,242 AFL++ tuples over the toml, toml_parser and toml_datetime sources. rtoml is a PyO3 wrapper; its lexer and parser are the same toml_parser 1.1.5 release as the selected Rust `toml` and `toml_edit` paths, so it is a shared-family path, independent of tomli and tomlkit.

Unverified leads ([leads.json](leads.json)): toml 0.10.2 (145,147,540) fails the typed-scalars control, because `toml.loads` returns `datetime.time(0, 32)` for the local time `00:32:00.25` and drops its fractional seconds; the service-config control matches. Two more native extensions give both exact typed trees but are not runnable paths yet, because their parsers are compiled code that Python line coverage and the Python AFL++ bridge cannot see: pytomlpp 1.1.0 (43,243; pybind11 over C++ toml++, checked on linux/amd64 because no aarch64 wheel exists) and toml-rs 0.4.3 (18,062; PyO3 over a Rust parser taken from a git branch). Each needs a source build with native coverage and AFL++ instrumentation of the wrapped parser. pytoml 0.1.21 (337,081) rejects the hexadecimal integer of typed-scalars, and qtoml 0.3.1 (2,002) rejects its offset date-time with fractional seconds; both match service-config. tomli-w (85,996,374) is excluded as a writer.
