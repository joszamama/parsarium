# C++ × XML: selected parsers

6 control-verified third-party paths selected from five named format-specific libraries and a Debian `-dev` package lookup. The ceiling is ten; the selection is not padded. A path is an API or package route, not necessarily an independent parser engine.

## Primary within-cell adoption metric

Debian popcon installations of each library's `-dev` package(s) (`by_inst`), captured 2026-11-17 ([snapshot](registry-snapshot.json)). The search is a bounded comparison of five C++ XML parser libraries: tinyxml2, pugixml, Xerces-C++, libxml++ and RapidXML. RapidXML was added later from the same saved popcon snapshots after its scoped candidate passed verification. On 2026-11-18 the same snapshot was searched for other C++ XML `-dev` and framework packages ([lookup](registry-snapshot.json)); TinyXML (version 1) was added from it.

All six paths give the same structure on the catalog control. Xerces-C++, pugixml, TinyXML, libxml++, and RapidXML also pass the shared order control; TinyXML2 rejects its processing instruction, so the TinyXML2 path uses a second valid order control with only that instruction removed. pugixml, TinyXML, TinyXML2, and RapidXML preserve qualified names; adapter code resolves namespaces. RapidXML's default parse flags skip the processing instruction rather than rejecting it, so it uses the shared order control unchanged. libxml++ delegates actual parsing to libxml2. Its Docker build instruments the wrapper and the pinned libxml2 source; a parser-only probe shows stable, input-dependent AFL++ feedback and different covered `parser.c` lines across the two valid controls.

Xerces-C++ uses its own scanner. Its [parser-only probe](../../../projects/xml/cpp/xerces_c/parser-probe.cpp) calls `XercesDOMParser::parse` without DOM traversal or result formatting; the two valid controls differ by 274 stable scanner source lines and 473 repeat-stable AFL++ tuples ([feedback receipt](../../../fuzzing/afl-native/xml/cpp/xerces_c/differential.json)). The full harness separately checks the namespace-aware tree output.

RapidXML's documented `xml_document<>::parse<0>(char*)` parses in situ: it writes into the caller's buffer, which must be mutable and zero-terminated, so the adapter parses a copy. Its [parser-only probe](../../../projects/xml/cpp/rapidxml/parser-probe.cpp) calls only `parse<0>` with an AFL++ allowlist limited to `rapidxml.hpp`. The two valid controls give 38 and 45 repeat-stable tuples, a difference of 15, and 329 versus 374 covered header lines ([feedback receipt](../../../fuzzing/afl-native/xml/cpp/rapidxml/differential.json)); the full control run covers 413 `rapidxml.hpp` lines. Boost.PropertyTree's XML reader embeds a RapidXML-derived copy and is not counted as a separate engine: Boost 1.90.0's `detail/rapidxml.hpp` matches 84.2% of RapidXML 1.13's normalized non-trivial lines in sequence.

TinyXML 2.6.2 is the last upstream release of the original TinyXML, pinned as Debian's unmodified orig tarball (SHA-256 `15bdfdcec58a7da30adc87ac2b078e4417dbe5392f3afb719f9ba6d062645593`) and built with `TIXML_USE_STL` as Debian builds it; Debian's CVE and entity-encoding patches, which concern malformed input and output escaping, are not applied. It is a different code base from TinyXML2: only 51 of 1,698 normalized non-trivial lines of `tinyxmlparser.cpp` and `tinyxml.cpp` match `tinyxml2.cpp` in sequence (3.0%). `TiXmlDocument::Parse` keeps the order control's processing instruction as an unreported unknown node. The first control covers 672 TinyXML lines (449 in `tinyxmlparser.cpp`); the two valid controls differ by 160 covered source lines and 172 repeat-stable AFL++ tuples ([feedback receipt](../../../fuzzing/afl-native/xml/cpp/tinyxml/differential.json)).

## Standard API (unranked)

None. The ISO C++ working draft and cppreference's header index contain no XML header ([evidence](standard.json)).

## The metric is close

Homebrew install-on-request (365 days) orders the four libraries differently: tinyxml2 1,757, pugixml 1,270, Xerces-C++ 1,209, libxml++ 461. Debian dev installs, the one primary metric, put Xerces-C++ first by a wide margin (2,676 vs 1,503 for pugixml) and pugixml second, ahead of tinyxml2 (487). On Homebrew, tinyxml2 would lead and Xerces-C++ would be third; that order is a caveat, not a second ranking. RapidXML's 17 is a weak signal: all 17 `librapidxml-dev` installations report no recent use, and the count measures only the Debian package, not copies vendored into projects or embedded in Boost. It ranks fifth because the protocol keeps positive primary-metric paths in descending order without a minimum. RapidXML has no Homebrew formula. The 275 libxml++ dev installations sum `libxml++2.6-dev` (266), `libxml++-4.0-dev` (2), and `libxml++-5.0-dev` (7). Only the last matches the verified ABI-5 release family. Homebrew's 461 corresponds to its older 2.42.4 formula. Source-level popcon is not used: libxml++2.6's 79,794 is a runtime package pulled in by dependents, and 79,361 of those installs show no recent file access.

## Search limit

The bounded search compared five named, format-specific C++ XML libraries and then looked up C++ XML `-dev` and framework packages in the same popcon snapshot. Xalan-C++, XQilla, CodeSynthesis XSD and XMLTooling run over Xerces-C++; gdome2's C++ wrapper runs over libxml2; gSOAP (95 dev installations; its generic DOM needs generated serializers) and Arabica (2; a wrapper over expat, libxml2 or Xerces-C++) are unresolved; libstudxml has no Debian package. Other C++ XML packages may exist and their adoption remains unmeasured here. The two small valid controls do not establish complete XML 1.0, DTD/entity, encoding, or malformed-input behavior. No standard-library XML API was found in the official inventory.

Qt XML, Boost.PropertyTree and POCO XML are parts of larger frameworks and are not ranked by whole-framework installs. Qt Core `QXmlStreamReader` and POCO XML `SAXParser` both passed local control and feedback checks but are not selected: Qt has only the framework-wide `qt6-base-dev` count (4,942), and POCO's XML-specific runtime package has 887 installations, below the 1,000 format-specific fallback ([leads](leads.json)). POCO XML also shares the Expat family.
