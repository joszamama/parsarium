# Expansion inventory: JSON, XML and plain MP3

This is a research inventory for three new formats across the eight
ecosystems. Observed 2026-11-17. It follows [PROTOCOL.md](../../PROTOCOL.md),
but it is **not** part of the selected catalog: no third-party package here is
verified, none is selected, and none counts toward the ten-path ceiling.
`data/cells.json`, `catalog/` and `data/curation/` are unchanged.

## Formats

Definitions, scope rules and control expectations are in
[formats.json](formats.json).

| Key | Format | Valid controls |
| --- | --- | --- |
| `json` | RFC 8259 / ECMA-404 JSON text | [control.json](controls/control.json) |
| `xml` | XML 1.0 + Namespaces | [control.xml](controls/control.xml) |
| `mp3_plain` | Untagged MPEG-1/2 Layer III frames | [silent-plain-44k.mp3](controls/silent-plain-44k.mp3), [tone-plain-16k.mp3](controls/tone-plain-16k.mp3) |

`mp3_plain` is a separate cell from the existing `mp3_id3v2` cell. Its controls
have no ID3v1, ID3v2, APE or Xing/Info/VBRI data. A parser verified in
`mp3_id3v2` only by reading ID3 fields does not count here. A result needs to come
from the audio frames: frame headers, duration from a frame scan, or decoded
samples. Tag-only readers are excluded. Libraries that read tags and also scan
frame headers (mutagen, TagLib, jaudiotagger, getID3, mp3agic) stay leads until
they produce that frame-level result.

Controls come from `scripts/make_expansion_controls.py`. The JSON, XML and
silent MP3 controls are generated byte-for-byte. The silent MP3 is 38
hand-built MPEG-1 frames at 128 kbit/s, 44.1 kHz, mono. The tone control is a
440 Hz sine encoded with `-t` (no Info frame) by the LAME build recorded in
[tone-plain-16k.encoder.txt](controls/tone-plain-16k.encoder.txt). It is
MPEG-2 LSF at 16 kHz with 30 frames. The `LAME4.0` strings inside its frames
are encoder filler in the frame main data, not a tag. The checker walks every
frame to EOF. ffprobe/ffmpeg 9.0.2 confirmed the control values in
`formats.json` (38/30 frames, 43,776/17,280 samples). This only checks the
controls. It does not verify FFmpeg as a candidate.

`SSL_CERT_FILE=/etc/ssl/cert.pem`):

```sh
python3 scripts/make_expansion_controls.py --tone
python3 scripts/capture_expansion_registry.py
python3 scripts/capture_expansion_metrics.py
python3 scripts/run_expansion_standard_controls.py
python3 scripts/build_expansion_inventory.py

```

Live registries change, so a re-capture will not match these snapshots exactly.
The checker validates the committed snapshots.

## Standard and runtime APIs

Standard and runtime APIs fall outside the ten-path ceiling. Each cell records
the official documentation it relied on. The local receipts cover:

- **Python 3.13.1:** `json.loads`; `xml.etree.ElementTree`, `xml.dom.minidom`
  and `pyexpat`. All three XML APIs use the bundled Expat family.
- **Go 1.27.1:** `encoding/json.Unmarshal` and `encoding/xml.Decoder.Token`.
  The default `encoding/json` build uses the v2 implementation (`JSONv2: true`
  in [Go's pinned build configuration](https://github.com/golang/go/blob/go1.27.1/src/internal/buildcfg/exp.go#L87)). The public `encoding/json/v2`
  and `jsontext` APIs were not run as separate paths.
- **PHP 8.5.12:** `json_decode` (a core extension, always enabled since 8.0);
  SimpleXML, DOM and XMLReader, which share libxml2. These XML extensions are
  enabled by default but are not guaranteed in every build.
- **OpenJDK 21.0.2:** DOM (`DocumentBuilder`) and StAX (`XMLStreamReader`).
  Java SE has no JSON package. `AudioSystem.getAudioFileFormat` rejected both
  MP3 controls; this is a recorded negative probe.
- **JavaScript:** no receipts. The local Node.js 26.10.0 binary does not start
  because its Homebrew `libsimdjson.33.dylib` is missing. `JSON.parse`, browser
  `DOMParser` and browser `decodeAudioData` are documented but still pending
  for these controls. The Node.js API index lists no XML parser and no MP3
  decoder.
- **C, C++ and Rust:** none documented in the scoped standard libraries.

## Adoption metrics

Metrics are compared only within one cell, following the existing cells:

| Ecosystem | Metric |
| --- | --- |
| npm | Downloads in the last month |
| PyPI | Last-month downloads from pypistats |
| crates.io | `recent_downloads` (90 days) |
| Packagist | Lifetime downloads |
| Go | pkg.go.dev "Imported by" |
| Maven | deps.dev `directDependentCount` of the default version |
| C/C++ | Homebrew install-on-request over 365 days |

`lead_adoption_order` orders unverified leads only. It is not a selection.
Known distortions:

- **C/C++:** formula-level counts are dominated by CLIs and umbrella packages,
  such as `jq` for JSON, `boost`, `folly` and `qtbase` for C++, and `ffmpeg`
  for MP3.
- **PHP and npm:** wrappers around the runtime parser rank high. Examples are
  `nette/utils`, `symfony/serializer` and `parse-json`. The protocol excludes
  same-family duplicates when it selects.
- **Java:** the deps.dev version-level count heavily favours older default
  versions (`json-simple` 1,163 vs `jackson-core` 178). It is a weak signal.
  No Java ranking should be taken from it without the curation exceptions the
  existing cells use.
- **Missing metrics:** `dsl-json` returned 404 from deps.dev. `minimp3`,
  `dr_mp3`, `libroxml`, `tinyxml`, `jsoncons` and `essentia` have no Homebrew
  formula. Their values stay `null` with the reason recorded.

## Search limits

- Each query records only the first 100 hits.
- **PyPI:** project-name substring matches with no relevance order. 3,937 names
  contain "json", so most were not inspected. `mpegaudio` matched 1 irrelevant
  name.
- **Maven Solr:** results are noisy. `mp3` mostly matched unrelated `*-mp`
  artifacts, and `mpeg audio` returned 0 hits.
- **pkg.go.dev:** the HTML search shows no total count, so `total` is `null`.
- **npm:** `json` has 367,349 total hits, so only the first page was inspected.
- **Homebrew:** C and C++ share one formula index, searched by name and
  description.
- **Targeted leads:** these came from project documentation knowledge and are
  labelled `targeted_documentation_lead`. The API names were not checked
  against pinned releases (`api_lead_checked_against_pinned_release: false`).

## Ambiguities and shared families

- **Superset parsers:** JSON5, Hjson, JSONC and UCL can claim only the
  strict-JSON control subset.
- **XML wrappers:** many XML leads tokenize through another parser. Go leads
  mostly use `encoding/xml`; dom4j, JDOM and XOM delegate to a JDK SAX parser;
  xml2js, xml-js and xmldoc use `sax`; and libxml2 sits behind lxml,
  libxmljs2, libxml++, `lestrrat-go/libxml2` and PHP DOM. See
  `shared-families.json`. libxml2 spans 6 ecosystems; minimp3 and mpg123
  each span 3–5.
- **HTML parsers with an XML mode:** `htmlparser2` and `jsoup` are flagged as
  ambiguous scope.
- **MP3 header scanners vs decoders:** header scanners (tcolgate/mp3,
  codec-parser, mp3-duration, TagLib properties) and full decoders produce
  different observables. A verified path must name its observable.
- **External processes:** `pydub`, `php-ffmpeg` and `phplame` call external
  CLIs and are excluded. Build-dependent backends are leads with that caveat:
  `sox`, `sdl2_mixer`, `audioread`, `rodio`, and `ijson` for JSON.

## YAML pilot searches

YAML was added later as a pilot format and is not part of this inventory
snapshot. `scripts/capture_yaml_registry.py` reuses the registry search
functions above with the query `yaml` (first 100 hits) and records one primary
value per named lead, using the metric of each ecosystem's JSON and XML pilot
cells (Debian popcon `sourcemax` for C and C++). It writes
`data/<ecosystem>/yaml/registry-snapshot.json`; the cell rules are in
[catalog/yaml/PROTOCOL.md](../../catalog/yaml/PROTOCOL.md).

## SQL (added later)

SQL was added as a later pilot format after this inventory. Its definition is
the `sql` entry in [formats.json](formats.json), and its scope, controls and
oracle are in [catalog/sql/PROTOCOL.md](../../catalog/sql/PROTOCOL.md). Its
bounded searches are not under `registry/`. They go straight to the pilot cells
as `data/<ecosystem>/sql/registry-snapshot.json`, together with each ecosystem's
primary metric for the targeted leads:

```sh
python3 scripts/snapshot_sql_registry.py
python3 controls/sql/check_controls.py
```

The JSON and XML snapshots and their checker above are unchanged.
