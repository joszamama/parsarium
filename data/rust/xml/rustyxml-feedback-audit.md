# RustyXML 0.3.0: unselected feedback audit

The pinned [RustyXML release](https://static.crates.io/crates/RustyXML/RustyXML-0.3.0.crate) has SHA-256 `8b5ace29ee3216de37c0546865ad08edef58b0f9e76838ed8959a84a990e58c5`. Its MIT and Apache-2.0 license files have SHA-256 `e36cdd9db3545a42292211f451d53db2d9a4a287fcdcaf06b2be93c3ec7c2430` and `a60eea817514531668d7e00765731449fe14d059d3249e0bc93b36de45f759f2`. The source's `src/parser.rs` says this parser derives from OFXMLParser in ObjFW, with the original author's permission.

The documented `xml::Parser::new(); feed_str(&str)` API yielded namespace-aware SAX-like events for [catalog-ns.xml](../../../controls/xml/catalog-ns.xml) and [order-default-ns.xml](../../../controls/xml/order-default-ns.xml). An adapter reported the same root, expanded element names, namespace declarations, decoded text, and depth as the selected Rust XML paths. `StartTag.attributes` is a HashMap, so attributes were sorted before comparison. Both exact control summaries matched. A Rust 1.99.1/Linux arm64 Docker build with LLVM source coverage covered 285 RustyXML lines, including 266 in `src/parser.rs`.

The first AFL++ overlay instrumented the whole Rust binary with cargo-afl 0.18.2. On three identical runs per valid control, its stable-edge ratios were 0.992748 and 0.993926; the stable cores differed by 65 and 142 edges. To exclude harness and runtime modules, a second build used a rustc wrapper to add `sancov-module`, `trace-pc-guard`, and `trace-compares` only when compiling the pinned RustyXML crate; the final binary linked AFL++'s compiler runtime. Its map size fell from 10,516 to 3,078. On ten separate runs, catalog feedback contained 553 edges in every run, while order feedback contained 621 edges once and 613 edges nine times (stable ratio 0.987118). Function-entry-only sanitizer coverage still varied on both controls.

LLVM source-coverage segment maps for the pinned RustyXML crate were identical across five separate executions of each control: catalog hash `97c20d36ca52` repeated 5/5 and order hash `aa6176c4ea50` repeated 5/5. The remaining AFL variance is inferred to arise from instrumented generic/runtime code monomorphized into the parser crate, including HashMap operations; those edges cannot be isolated by this stable Rust sanitizer-coverage build. Exact repeatable parser-scoped AFL feedback is therefore **not verified**, and RustyXML remains an unresolved lead. No malformed input or fuzzing campaign was run.
