# JAVA × XML: selected parsers (pilot)

10 control-verified third-party paths and 1 control-verified standard path. The third-party ceiling is ten; this pilot builds five independent XML parser engines and five format-specific package API paths (dom4j, XMLBeans, JDOM2, and XOM over the JDK Xerces fork; Jackson XML over Woodstox), and does not pad the selection. A path is an API or package route, not necessarily an independent parser engine.

Jackson XML is ranked as a format-specific parsing API under the selection protocol. Its 25,682 package adoption count does not imply a new independent tokenizer; it shares Woodstox with the woodstox-core path. Two higher-metric excluded leads are jsoup (7,010), an HTML parser whose XML mode is not namespace-aware, and XStream (4,001), a serializer over pluggable XML drivers. dom4j is ranked on the org.dom4j:dom4j coordinate alone (1,434 over 11 releases, rechecked unchanged on 2026-11-17). The legacy dom4j:dom4j 1.x coordinate (1,755) is the same project; it stays in the lead log and is not added or counted as a second path. dom4j has no tokenizer: `SAXReader` obtains its reader from `SAXParserFactory.newInstance()`, which on the pinned runtime is the OpenJDK java.xml Xerces fork. The protocol accepts it as a wrapper package path; it shares the Apache Xerces2-J family with xercesImpl and the standard path and is not an independent parser engine.

The xercesImpl, XOM, and kXML2 release jars lack line-number tables, so their pinned same-release sources are recompiled with `javac -g --release 8`. The Woodstox, dom4j, XMLBeans, JDOM2, Aalto, XPP3, and Jackson XML release jars include line tables; JaCoCo covers their pinned release classes directly and maps them to their same-release sources jars. Jackson XML module lines (320) and underlying Woodstox StAX lines (832) are recorded separately on the first control. XMLBeans 5.4.1 is a JAXP SAX tree builder, not the Piccolo-derived tokenizer previously suspected: its SAXHelper calls SAXParserFactory.newInstance(). JaCoCo reported 1,004 XMLBeans own source lines and separately 3,733 OpenJDK Xerces lines on the first control. JDOM2 separately covered 734 own lines, including SAXBuilder, SAXHandler and tree classes, and 3,549 underlying OpenJDK Xerces SAX lines. XOM separately covered 579 own tree-builder lines and 3,488 OpenJDK Xerces SAX lines. XPP3 covered 677 own MXParser tokenizer lines and kXML2 covered 377 own KXmlParser lines; neither uses a JDK XML tokenizer. For dom4j, the underlying JDK Xerces fork is instrumented as boot classes and reported separately against the jdk25u `jdk-25.0.5+8` sources (3,601 lines in 62 files on the first control). The [parser records](parsers.json) have the details.

## Standard API

`javax.xml.parsers.DocumentBuilder.parse(InputStream)` from a namespace-aware `DocumentBuilderFactory.newInstance()` on OpenJDK 25.0.5 ([docs](https://docs.oracle.com/en/java/javase/25/docs/api/java.xml/javax/xml/parsers/DocumentBuilder.html#parse(java.io.InputStream))). The default factory is `com.sun.org.apache.xerces.internal.jaxp.DocumentBuilderFactoryImpl`, a repackaged fork of Xerces2-J inside `java.xml`. **The xercesImpl and standard paths share the Apache Xerces2-J parser family.** They are separate, diverged code copies, not one binary. Sources come from the `jdk-25.0.5+8` tag of openjdk/jdk25u. Details in [standard.json](standard.json).

## Feedback

All eleven paths (ten third-party and one standard) map JaCoCo source lines into AFL++ tuples. Repeated control runs give identical features, and `controls/xml/order-default-ns.xml` changes them ([afl-feedback.json](afl-feedback.json)). The namespace-aware paths produce the expat oracle output used for the Go and Python XML cells. Jackson XML instead reports its own ordered token projection, omitting namespace URIs, root name, comments, processing instructions, and attribute origin.

Woodstox feedback covers its StAX reader and scanner classes (815 pinned source lines on the first control). Aalto covers 1,427 pinned source lines, repeated valid controls are stable, and the two controls differ by 278 parser features and 277 AFL++ tuples. dom4j feedback is scoped to its own org.dom4j package lines (723 on the first control, mostly `SAXContentHandler`, `NamespaceStack`, `SAXReader`, and tree classes), not to the JDK Xerces fork; ten repeated traces per control were identical, and the two controls differ by 125 parser features and 125 AFL++ tuples. XMLBeans feedback is scoped to its own tree/SAX helper source lines, not the JDK Xerces fork; three repeated traces of each valid control were identical, and the controls differed by 90 XMLBeans source features and 89 AFL++ tuples. JDOM2 feedback is scoped to its own JDOM source lines; repeated valid controls were stable and differed by 146 source features and 144 AFL++ tuples. Jackson XML module feedback repeated stably; the second valid control changed 17 module source features and 17 AFL tuples. The Woodstox SymbolTable cache is outside that feedback scope because its process-dependent paths changed across identical replays; this does not exclude reader or scanner coverage.

XOM feedback is scoped to its own `nu.xom` source lines. Three repeated traces of each valid control were identical; the controls differed by 72 source features and 72 AFL tuples. The JDK Xerces tokenizer is reported separately on the valid control and is not counted as a second independent XOM engine. XPP3 feedback is scoped to `org.xmlpull.mxp1` MXParser tokenizer lines; three traces per control were identical, with 160 source features and 160 AFL tuples differing. The requested 1.1.3.4 artifact was unavailable from Maven Central, so the published 1.1.4c release of the same coordinate is pinned.

kXML2 feedback is scoped to `org.kxml2.io` KXmlParser tokenizer lines. Three traces per control were identical, and the controls differed by 29 parser source features and 29 AFL tuples. The pinned published JAR remains in the image; a same-release source rebuild supplies line tables absent from that JAR.
