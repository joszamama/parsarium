**netty-codec-dns 4.2.21.Final** (Apache-2.0) parses local bytes with `new DatagramDnsResponseDecoder() / new DatagramDnsQueryDecoder() in an EmbeddedChannel, fed new DatagramPacket(ByteBuf, recipient, sender)`. Both controls match the oracle summary. The response control covers 414 library lines in 15 files. AFL++ feedback repeats 3 times per control; response and query give 414/277 parser features and 433/295 AFL++ tuples, differing by 251 features and 250 tuples ([receipt](netty-codec-dns-feedback-differential.json)). Own Java decoder; Vert.x's DNS client and Netty's DnsNameResolver use it. Netty leaves A/AAAA (and MX/CNAME after decompression) as raw records, so the harness formats addresses from the decoded bytes and reads names with the public DefaultDnsRecordDecoder.decodeName. DnsQuery carries no AA/TC/RA/RCODE; they are reported as 0 for the query control.

**dnsjava 3.7.1** (BSD-3-Clause) parses local bytes with `org.xbill.DNS.Message(byte[] b) throws IOException`. Both controls match the oracle summary. The response control covers 467 library lines in 21 files. AFL++ feedback repeats 3 times per control; response and query give 467/376 parser features and 487/396 AFL++ tuples, differing by 91 features and 91 tuples ([receipt](dnsjava-feedback-differential.json)). Own Java decoder; keeps the raw flags word, so Z, AD and CD are all reported. Presentation text is dnsjava's rdataToString except AAAA, which the harness formats from the decoded 16 bytes as RFC 5952 text.

**pcap4j-core 1.8.2** (MIT) parses local bytes with `org.pcap4j.packet.DnsPacket.newPacket(byte[] rawData, int offset, int length) throws IllegalRawDataException`. Both controls match the oracle summary. The response control covers 575 library lines in 14 files. AFL++ feedback repeats 3 times per control; response and query give 575/437 parser features and 595/457 AFL++ tuples, differing by 138 features and 138 tuples ([receipt](pcap4j-core-feedback-differential.json)). Own Java decoder inside the Pcap4J packet library (pinned to 1.8.2, the latest non-pre-release; 2.0.0-alpha.6 is the deps.dev default). The documented DnsPacket.newPacket(byte[], int, int) decodes a DNS message from caller-supplied bytes; no capture handle, interface or libpcap call is used (JNA is on the class path but never loads a native library). RDATA comes from the documented runtime module pcap4j-packetfactory-static 1.8.2. Pcap4J keeps the reserved Z bit, AD and CD. Names are decompressed with the documented DnsDomainName.decompress(message); for a name that is only a compression pointer Pcap4J returns a leading '.', which the harness drops. AAAA text is formatted by the harness from the decoded 16 bytes (RFC 5952). Its deps.dev count covers the whole multi-protocol pcap4j-core artifact. Coverage and AFL++ features are scoped to Pcap4J's DNS classes (org.pcap4j.packet.Dns*, namednumber.Dns*, StaticDnsRDataFactory and util.ByteArrays): building the first RDATA loads the static factory binder, which initialises every protocol's named-number tables (TcpPort, UdpPort, IpNumber and others) and would otherwise make up most of the response control's features.

**minidns-core 1.1.3** (Apache-2.0) parses local bytes with `org.minidns.dnsmessage.DnsMessage(byte[] data) throws IOException`. Both controls match the oracle summary. The response control covers 458 library lines in 20 files. AFL++ feedback repeats 3 times per control; response and query give 458/377 parser features and 478/397 AFL++ tuples, differing by 81 features and 81 tuples ([receipt](minidns-core-feedback-differential.json)). Own Java decoder of the MiniDNS project (formerly de.measite.minidns, an old coordinate of the same code that is not counted); the minidns-core artifact holds the message model and parser, while the resolver and client live in other artifacts that the harness does not load. MiniDNS decodes AD and CD but not the reserved Z bit, so z carries AD and CD only (both controls have all three bits clear). Names are DnsName.ace (lower-cased ACE text); A text is MiniDNS's own toString; AAAA text is formatted by the harness from the decoded 16 bytes (RFC 5952), because MiniDNS prints uncompressed groups.

**dns4s-core_2.13 0.21.0** (Apache-2.0) parses local bytes with `com.github.mkroli.dns4s.Message.apply(bytes: MessageBuffer): Message, with MessageBuffer.apply(buf: java.nio.ByteBuffer) (Scala companion objects, called from Java as Message$.MODULE$ and MessageBuffer$.MODULE$)`. Both controls match the oracle summary. The response control covers 170 library lines in 9 files. AFL++ feedback repeats 3 times per control; response and query give 170/84 parser features and 190/104 AFL++ tuples, differing by 86 features and 86 tuples ([receipt](dns4s-core-feedback-differential.json)). Own Scala decoder of the dns4s project (Michael Krolikowski), counted in the Java cell as a JVM library, as Scala and Kotlin libraries such as circe-yaml and ktoml are in other Java cells; it uses no other DNS library. The Scala 2.13 build is pinned and ranked by its own coordinate (dns4s-core_3 and older Scala builds of the same code are not counted separately). The harness calls the core decoder only; the Akka, FS2 and Netty integrations live in other artifacts and are not loaded, and the Guava dependency is used only by the DSL package, which is not loaded. dns4s's HeaderSection decodes neither the reserved Z bit nor AD/CD, so z is reported as 0 (both controls have all three bits clear). A/AAAA are java.net.Inet4Address/Inet6Address built from the decoded bytes (InetAddress.getByAddress, no lookup): A text is getHostAddress(), AAAA text is formatted by the harness from getAddress() (RFC 5952). The case-class fields `type` and `class` are read through productElement.

## Checked, excluded or recorded separately

- **de.measite.minidns:minidns-core** (excluded): Old Maven coordinate of MiniDNS; same family as org.minidns:minidns-core.
- **io.vertx:vertx-core** (excluded): The DNS client is a network API over Netty's codec; no documented message-bytes parser of its own. Its count is for all of vertx-core.
- **org.xbill:dnsjava** (excluded): Not on deps.dev (404); the published coordinate is dnsjava:dnsjava.
- **org.asynchttpclient:netty-codec-dns** (excluded): Backport copy of Netty's DNS codec for async-http-client (parent netty-bp; 2.0.40 ships io.netty.handler.codec.dns classes such as DatagramDnsResponseDecoder and DefaultDnsRecordDecoder under the Netty/Codec/DNS name). It is an older copy of the selected netty-codec-dns family, not a separate parser.
- **io.netty:netty5-codec-dns** (excluded): Netty 5 alpha line (default 5.0.0.Alpha5) of the selected netty-codec-dns codec; same project and family, pre-release only.
- **com.helger.web:ph-dns** (excluded): DNS helper library over dnsjava (11.5.1 POM depends on dnsjava); no own message parser.
- **com.spotify:dns** (excluded): SRV lookup/resolver wrapper over dnsjava (3.3.2 POM depends on dnsjava); network API, no own message parser.
- **org.nhind:dns** (excluded): Direct Project DNS server application (9.0.0 jar: DNSServer, UDPServer, TCPServer, Spring Boot autoconfiguration); no documented API that parses caller-supplied message bytes.
- **com.qiniu:happy-dns** (excluded): Resolver library; its wire parser com.qiniu.android.dns.dns.DnsResponse is package-private (2.0.1 sources), so there is no public API for caller-supplied message bytes.
- **com.davfx.ninio:ninio-dns** (excluded): Asynchronous DNS client (3.0.50 sources: DnsClient, DnsConnecter, DnsRequestBuilder); network API with no documented message-bytes parser.
- **cc.otavia:otavia-codec-dns_3** (excluded): No DNS message decoder: the 0.4.5 sources jar holds only cc.otavia.dns.DatagramDnsQueryResolver and codec/DnsQueryEncoder (a query encoder for otavia's resolver), so it cannot parse caller-supplied message bytes. Scala 3 framework codec; Scala artifacts would otherwise count in this cell.
- **com.github.mkroli:dns4s-core_3** (excluded): Scala 3 build of the same dns4s core sources as the selected dns4s-core_2.13; one Scala binary-version coordinate is counted.
- **org.jmdns:jmdns** (excluded): Multicast DNS service-discovery library. Its message reader javax.jmdns.impl.DNSIncoming sits in the implementation package (the documented API is JmDNS/ServiceInfo discovery), and by source inspection of 3.6.5 it handles only A, AAAA, CNAME, PTR, TXT, SRV, HINFO and OPT: the MX answer of controls/dns/response.bin falls to the default branch and is skipped, so the control cannot be reproduced.
- **org.apache.pekko:pekko-actor_2.13** (excluded): The DNS message codec in Pekko's actor IO module (org.apache.pekko.io.dns.internal.Message.parse in the 2.0.0 sources) is declared private[internal] and annotated @InternalApi ('INTERNAL API'); the documented API is the async DNS resolver extension, not a message-bytes parser. No metric looked up.
