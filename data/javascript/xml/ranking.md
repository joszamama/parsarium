# JAVASCRIPT × XML: selected parsers (pilot)

10 control-verified third-party paths selected. This bounded pilot ranks format-aware XML input APIs, including limited raw-name and raw-CST routes, with each underlying parser family recorded, documented local input APIs, valid-control results, and AFL++ feedback. A path is an API or package route, not necessarily an independent parser engine.

The saxes and sax APIs take string chunks; their adapters decode local bytes with strict UTF-8 `TextDecoder` before calling their documented write/close streams. fast-xml-parser receives the local `Buffer` through its documented `XMLParser.parse(data, true)`, which decodes it and runs the package's own validator before its parser. It keeps qualified names and has no namespace URI resolution, so the adapter resolves prefixes from in-scope `xmlns` attributes; numeric character references decode only with its documented `htmlEntities` option, which also admits common HTML named entities. Entity decoding runs in its dependency @nodable/entities 3.1.0, outside the counted package source. @xmldom/xmldom accepts locally decoded text through its `DOMParser.parseFromString(text, 'application/xml')`, parses it with its own `XMLReader` in `lib/sax.js` (unrelated to the sax package), and builds a DOM; the adapter makes every reported warning or error fatal and reads the DOM's namespace resolution. xml2js is a wrapper path: its documented `Parser.parseStringPromise` takes locally decoded text, drives `sax.parser(true, {xmlns: true})`, and builds its ordered tree from sax events. The dependency range resolves to sax 1.6.1, the same release as rank 4; package and underlying tokenizer coverage are recorded separately. Its tree drops comments and processing instructions, so text split only by those nodes is reported as one segment. jsdom is also a wrapper path: its documented `new JSDOM(text, {contentType: 'application/xml'})` takes locally decoded text, and its XML document parser (`lib/jsdom/browser/parser/xml.js`) drives `SaxesParser({xmlns: true, forceXMLVersion: true})` and builds DOM nodes from saxes events, throwing on the first saxes error. The dependency range resolves to saxes 6.0.0, the same release and integrity as rank 1. The receipt counts jsdom package lines (mostly module load and window setup), its XML parser file alone, and saxes lines separately; AFL++ feedback comes from a construction-only run without the adapter's DOM read-back. jsdom copies `<!ENTITY name "value">` declarations from the DOCTYPE into saxes' entity table and forces XML 1.0 rules. The ten paths cover six parser families. saxes forked sax-js and later rewrote its parser, so they have historical lineage but distinct parser implementations. htmlparser2 adds its own forgiving XML-mode tokenizer and entity decoder; its raw-name event output matches a non-namespace Expat projection on both valid controls, but it neither checks full XML well-formedness nor resolves namespace URIs. Its very large package-download metric mostly measures HTML parsing and is not XML-mode use. xmldoc adds a tree builder over sax 1.6.1; it also reports raw names only and omits the prolog comment/PI. Both have parser-scoped differential AFL feedback, with no adapter-side namespace repair. xml-js adds an ordered tree builder over the same sax 1.6.1 tokenizer as sax and xml2js; its own 163 source lines and 888 underlying sax lines are recorded separately. Parser-only sax AFL feedback differs by 40 stable source ranges and tuples across the valid controls. @xml-tools/parser defines its own XML grammar over Chevrotain; its two valid controls match an independent Expat raw-QName hierarchy. The CST keeps quoted attribute token images and reports zero lex/parse errors but does not provide expanded namespace names or decoded entity text. Its AFL guidance records parser ALT callback hit counts: 11 grammar ranges change across three identical repeats per control, producing 22 different features and tuples; read/decode-only baselines are identical. This measures execution frequency, not new branches or lines. Each package download count includes transitive adoption.

## Standard API (unranked)
