Each path turns both valid controls into the exact typed tree of `catalog/toml/PROTOCOL.md` ([verification.json](verification.json)). smol-toml parses with its own code in `dist/parse.js`, `dist/struct.js`, `dist/extract.js` and `dist/primitive.js`; toml-eslint-parser runs its own tokenizer and parser in `lib/index.mjs`; @ltd/j-toml runs its own line-iterator parser and literal decoders in `index.mjs`, with `bigint: true` (integers as BigInt) and `joiner: '\n'` (multi-line string lines joined with LF); @decimalturn/toml-patch runs its own tokenizer, format-preserving syntax-tree parser and value conversion in the published bundle `dist/toml-patch.js`, with its documented `integersAsBigInt: true` option. They share no code. AFL++ feedback is scoped to each package's V8 source ranges; three repeats per control are identical, and the controls differ by 118 tuples (smol-toml), 156 tuples (toml-eslint-parser) 98 tuples (@ltd/j-toml) and 181 tuples (@decimalturn/toml-patch) ([afl-feedback.json](afl-feedback.json)). @ltd/j-toml covers 1,512 package lines on service-config and 1,536 on typed-scalars; its offset date-times are read with millisecond precision through the documented `getUTC*` getters. @decimalturn/toml-patch ships only a minified bundle of 83 long lines, so its 51 and 54 covered lines on the two controls understate the code reached; its AFL++ features are V8 source-offset ranges (238 on service-config), and its date-times keep millisecond precision.

@effected/toml 0.20.0 (targeted npm lookup, `round_4_targeted_lookups`) runs its own scanner, lossless syntax-tree parser and semantic analysis in `internal/scanner.js`, `internal/parser.js` and `internal/semantic.js` on the effect runtime (a declared peer dependency, outside the coverage subject). Its value-level `Toml.parse` returns safe integers as plain Numbers, so the path is the documented `TomlVisitor.visit` stream: TableStart/ArrayTableStart events with resolved paths and KeyValue events with resolved key paths and typed `TomlInteger`, `TomlFloat`, `TomlString`, `TomlBoolean`, `TomlDateTimeLiteral`, `TomlArray` and `TomlInlineTable` nodes. Date-times are formatted from the parser's field objects (offset date-times shifted to the UTC instant). It covers 2,156 package lines on service-config and 2,224 on typed-scalars; 224 and 251 AFL++ tuples, 115 differ, three identical repeats per control.

@sgarciac/bombadil 2.3.0 (targeted npm lookup, `round_4_targeted_lookups`; also in the toml-lang wiki list) defines its own TOML 0.5.0 tokens and grammar in `lib/lexer.js` and `lib/parser.js` and loads tables in `lib/tables.js`; the chevrotain runtime executes those definitions and is outside the coverage subject. Its README's full-typing mode `readToml(text, true)` returns `{ type, image, value }` primitives; the adapter reads only type and value. It covers 964 package lines on service-config and 982 on typed-scalars; 134 and 133 AFL++ tuples, 73 differ, three identical repeats per control.
