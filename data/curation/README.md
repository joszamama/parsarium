# Adoption evidence and ten-path selection

The [selection plan](plan.json) records every candidate that passed a valid
format control before the catalog is reduced to at most ten third-party paths
per format and ecosystem. It keeps the original parser and registry snapshot
hashes, the selected paths, and the reason for each exclusion. Standard and
runtime APIs are outside this limit.

The [metric exception report](metric-exceptions.json) is generated by
`python3 scripts/audit_curated_metrics.py`. All 776 paths in the current
selection have a positive numeric adoption signal: 728 use the primary
within-cell metric, 38 use a pinned Debian Popularity Contest installation
count, and 10 use a captured upstream GitHub star count. The latter two are
shown separately and never combined numerically with primary rankings.

Three further paths passed a valid format control and have positive primary
adoption metrics, but do not have a verified container control plus
parser-derived AFL++ feedback. Their [blockers](feedback-exclusions.json) are
recorded after the adoption ranking; their slots remain empty. The affected
cells select 9 JavaScript ASCII PLY paths and 8 Python ASCII PLY paths. The
original valid-control evidence remains in `preten/`. The former Python SVG
blockers for PyQt6 and PySide6 are resolved: both now run the pinned wheels
against QtSvg 6.12.0 built from source with LLVM coverage, as recorded in
[their blocker records](feedback-blockers/).

The report also records 217 excluded paths whose primary metric was missing,
zero, or whose parser family duplicated a stronger selected path. Of these,
20 have a secondary number below the selection threshold, 28 have a
qualifying secondary number but no space under the ten-path ceiling, and 168
have no secondary number recorded. These are **unresolved adoption signals**,
not claims that nobody uses the package. The remaining case is a byte-identical
PHP PLY parser family duplicate with a lower upstream star count.

One further candidate is excluded on eligibility grounds: the pinned
[`pymupdf4llm` 2.1 release](https://pypi.org/project/pymupdf4llm/2.1/) is
explicitly an empty compatibility distribution. Its PDF parsing code is in
PyMuPDF, already selected for the Python PDF cell. The next control-verified
candidate, `pdf2docx`, takes the vacated slot with its recorded PyPI download
metric. This is recorded separately from missing-metric exceptions.

The primary metrics come from each cell's `registry-snapshot.json`. Debian
counts are from [Popularity Contest](popcon-snapshot.json) and its pinned
[`by_inst.gz`](popcon-sourcemax-by_inst.gz) snapshot; they measure installed
source packages among volunteers, not format-specific use. GitHub stars are
from [captured upstream repositories](github-supplemental-stars.json); they
measure repository interest, not package downloads. Neither signal is
comparable to another ecosystem's metric. A missing or zero primary value is
never silently replaced by an invented count.

Run `python3 scripts/plan_curated_catalog.py --write` to regenerate the plan
with the feedback exclusions, then `python3 scripts/audit_curated_metrics.py`
to regenerate and validate the exception report. The protocol is in
[PROTOCOL.md](../../PROTOCOL.md).

## MP3 merge

The former "MP3 with ID3v2" format and the plain-MP3 pilot are one MP3 format.
Its plan cells rank the union of the paths that either former cell had
selected; the pre-merge ID3v2 candidates and their exclusions remain in
`preten/<ecosystem>/mp3_id3v2_precuration/`, and the plain-MP3 pilot evidence
in `data/<ecosystem>/mp3/plain-mp3-pilot/`. C, Go, JavaScript and Python were
re-ranked from one fresh capture
(`scripts/snapshot_mp3_merge_metrics.py`). The [merge record](mp3-merge.json)
lists every kept path, the 6 paths removed below the top ten, and the 25
duplicate package paths removed in favour of the ID3v2-control project.
