# Adoption evidence and ten-path selection

The [selection plan](plan.json) records every candidate that passed a valid
format control before the catalog is reduced to at most ten third-party paths
per format and ecosystem. It keeps the original parser and registry snapshot
hashes, the selected paths, and the reason for each exclusion. Standard and
runtime APIs are outside this limit.

The [metric exception report](metric-exceptions.json) is generated by
`python3 scripts/audit_curated_metrics.py`. All 775 paths in the current
selection have a positive numeric adoption signal: 727 use the primary
within-cell metric, 38 use a pinned Debian Popularity Contest installation
count, and 10 use a captured upstream GitHub star count. The latter two are
shown separately and never combined numerically with primary rankings.

The report also records 229 excluded paths whose primary metric was missing,
zero, or whose parser family duplicated a stronger selected path. Of these,
20 have a secondary number below the selection threshold, 28 have a
qualifying secondary number but no space under the ten-path ceiling, and 180
have no secondary number recorded. These are **unresolved adoption signals**,
not claims that nobody uses the package. The remaining case is a byte-identical
PHP PLY parser family duplicate with a lower upstream star count.

The primary metrics come from each cell's `registry-snapshot.json`. Debian
counts are from [Popularity Contest](popcon-snapshot.json) and its pinned
[`by_inst.gz`](popcon-sourcemax-by_inst.gz) snapshot; they measure installed
source packages among volunteers, not format-specific use. GitHub stars are
from [captured upstream repositories](github-supplemental-stars.json); they
measure repository interest, not package downloads. Neither signal is
comparable to another ecosystem's metric. A missing or zero primary value is
never silently replaced by an invented count.

Run `python3 scripts/plan_curated_catalog.py --write` to regenerate the plan,
then `python3 scripts/audit_curated_metrics.py` to regenerate and validate the
exception report. The protocol is in [PROTOCOL.md](../../PROTOCOL.md).
