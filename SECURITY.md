# Security policy

This policy covers Parsarium itself: the `parsarium` Python package, the harnesses, Dockerfiles and scripts in this repository, and the website. Bugs in the third-party parsers that Parsarium runs belong to their own projects; see [Bugs in third-party parsers](#bugs-in-third-party-parsers).

## Reporting a vulnerability in Parsarium

Please report privately through [GitHub private vulnerability reporting](https://github.com/joszamama/parsarium/security/advisories/new). Do not open a public issue for a security problem.

Useful reports include:

- the affected component (package version from `parsarium --version`, or the commit and file);
- what an attacker could do, and under which conditions;
- steps or a minimal input to reproduce it.

We aim to acknowledge reports within a week. We will agree on a disclosure date with you once a fix is ready, and credit you in the release notes unless you prefer otherwise.

Examples of problems in scope: the package extracting files outside its cache directory, accepting a snapshot that does not match its pinned SHA-256, a harness or script that runs untrusted input outside its container, or a run script generated by the bench that executes something other than the selected targets.

## Supported versions

Fixes go into the latest release on PyPI. Older releases stay pinned to their snapshots and are not patched.

## Bugs in third-party parsers

If you find a crash, hang, or other bug in a parser while using Parsarium, report it to that parser's maintainers through their own security policy, not here. Check whether it reproduces on their latest release, and remember that several packages often share one engine: one report to the shared library is better than many reports to its wrappers. [ETHICS.md](ETHICS.md) and the [triage and disclosure chapter](https://parsarium.com/manual/triage-and-disclosure/) of the manual describe the process.
