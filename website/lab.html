CHAPTER 1 · THE AGREEMENT

A format tells the program what to expect.

A parser receives input and tries to recognize a structure. The format describes the possible parts and their order; the program chooses an API and an implementation to read them. A valid control gives us one concrete example that should pass.

That is why the first question in Parsarium is practical: which program and input API will receive this file, text, or stream? The same format can reach many programs with different code behind the API.

Grammar

The rules for how an input is organized. They may describe binary chunks, text tokens, nested elements, or a protocol message.

CHAPTER 2 · THE GRAMMAR

Three tiny inputs, three kinds of structure.

These are the valid controls used in the exercise below. Notice how the parser must do more than check a filename.

PNGChunks

A PNG begins with a signature. Each following chunk has a length, a type, data, and a checksum. The IHDR chunk tells the decoder the image dimensions; IDAT carries compressed image data.

signature→IHDR→IDAT→IEND
Question for the parser: which dimensions and pixels do these chunks describe?
SVGElement tree

SVG is XML. A root <svg> element contains shapes and attributes. The browser builds an element tree before we inspect its width, height, and rectangles.

<svg width="2" height="1">├─ <rect fill="#ff0000">└─ <rect fill="#00ff00">
Question for the parser: which elements and attributes are present?
ASCII PNMTokens

In a P3 PNM image, plain text tokens carry a magic value, dimensions, a maximum channel value, then RGB samples. Whitespace separates tokens; the numbers still need checking.

P3→2 1→255→RGB × 2
Question for the parser: do the samples match the declared image size?

CHAPTER 4 · LESSONS TO KEEP

What a successful parse tells you.

The control establishes a starting point.

One valid input shows that the chosen API can reach format-aware code and produce an expected result. It does not describe every input that the parser accepts.

Structure and result are separate observations.

A file may have recognizable parts, while a program interprets them differently. Inspect both the format grammar and the output or fields the parser exposes.

Feedback belongs to a program.

Coverage says which implementation lines or edges executed for that input. It helps study the target program; a format has no coverage of its own.

Comparisons need the same ground rules.

Pin the release, input API, control, and harness. Record shared underlying parser families so two package names are not mistaken for independent engines.
