# Parsarium website

Static site at [parsarium.com](https://parsarium.com), generated by `build.py` from the catalog, project manifests, and receipts in this repository. English pages live at the root and Spanish pages under `/es/`.

## Pages

| Route | Template | What it does |
| --- | --- | --- |
| `/` | `pages/<lang>/index.html` | The `red-green.png` control as a hexdump, the targets that read it, the ten formats, and how to use Parsarium |
| `/bench/` | `pages/<lang>/bench.html`, `assets/bench.js` | Builds a target selection with a stable ID, a run script, a manifest, and a report table |
| `/atlas/` | `pages/<lang>/atlas.html`, `assets/atlas.js` | Format × language map and searchable parser list |
| `/manual/` | `pages/<lang>/manual.html` | Table of contents for the manual |
| `/manual/<slug>/` | `manual/<lang>/<slug>.html` | One chapter; order is set by `MANUAL` in `build.py` |
| `/about/` | `pages/<lang>/about.html` | Motivation, anatomy of a target, selection rules, receipt timeline, citation |

`/run/`, `/lab/`, and `/why/` redirect to the bench, the manual, and about.

Every template starts with a JSON comment holding its title and description (or summary for chapters). Placeholders such as `{{VERIFIED}}`, `{{RUNNABLE}}`, `{{FAMILIES}}`, `{{HEXDUMP}}`, `{{MANUAL_TOC}}`, and `{{COMMIT}}` are filled at build time; the build fails if any placeholder is left. `{{ROOT}}` and `{{ASSET_ROOT}}` resolve relative links.

To add a chapter, write `manual/en/<slug>.html` and `manual/es/<slug>.html` and add the slug to `MANUAL`.

## Preview locally

```sh
python3 website/build.py
python3 -m http.server 8765 --directory website/dist
```

The build writes `catalog.json` (used by the bench and atlas) and `manual.json` (used by the byte inspector in the manual). Commands in the copy should name runnable targets; the catalog's `targets` keys list them.

## Publish

The `Publish site` workflow builds and deploys to GitHub Pages on changes to `main`. Pages include the Cloudflare Web Analytics beacon.
