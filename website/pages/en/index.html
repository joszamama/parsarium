0x0020use it

Three ways to use it.

Install it from PyPI. It needs Python 3.11 or newer, and Docker to run targets.

$ python3 -m pip install parsarium

Run one file through one parser.

You get a JSON receipt with the input hash, the image ID, the exit status, and the time it took. It is the quickest way to check how a specific library handles a specific input.

$ parsarium show png python pillow
$ parsarium run png python pillow my.png

Send the same file to every parser.

Each target writes its own receipt and summary.json collects them. When parsers disagree about the same bytes, that is a good place to start looking.

$ parsarium run-format png --list
$ parsarium run-format png \
    --file my.png --results runs/png-my-file

Fuzz a parser with AFL++.

All runnable targets have an AFL++ overlay. C, C++, and Rust parsers are instrumented directly. Go, Java, JavaScript, Python, and PHP parsers send their coverage to AFL++ through a small bridge.

$ parsarium fandango setup
$ parsarium afl build png python pillow
$ parsarium afl prepare png python pillow runs/pillow --fandango 100
$ parsarium afl run runs/pillow --seconds 3600

Generate inputs with Fandango.

Every format has a default Fandango grammar: the Fanbase specs for PNG, ZIP, WAV, JSON and XML, and Parsarium's own for the other formats. Fandango writes valid inputs from the grammar, replays them through the target, and can hand them to AFL++ as seeds.

$ parsarium fandango setup
$ parsarium fandango generate png python pillow \
    runs/pillow-fandango --count 100 --seed 42 \
    --replay --prepare-afl

0x0030engines

Packages and the engines behind them.

Many packages wrap the same decoder. In PHP, most of the PNG packages read images through GD; in JavaScript, most PDF packages build on pdf.js. Parsarium records the parser family of every entry, so you decide what to count.

A study about ecosystems may want every package. A study about parser engines may want one target per family. The bench builds either selection and gives it an ID you can put in a paper.

0x0050about

Why it exists.

I'm José Antonio Zamudio Amaya, a PhD researcher at CISPA working on fuzzing and test generation for programs with complex inputs. Every study I ran started by picking parsers, installing them, and writing adapters. Parsarium is that work done once, carefully, and shared, so experiments can start from the same targets and their results can be compared.
