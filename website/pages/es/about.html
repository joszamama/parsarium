0x0000acerca de

Un conjunto compartido de targets para investigar parsers.

Soy José Antonio Zamudio Amaya, doctorando en CISPA, en Saarbrücken. Trabajo en fuzzing y generación de pruebas para programas cuyas entradas tienen estructura: archivos, peticiones y mensajes de protocolo. Parsarium es el conjunto de targets que construí para ese trabajo, publicado para que otras personas también puedan usarlo.

0x0010por qué

Por qué lo construí.

Casi todos los estudios sobre pruebas de parsers empiezan igual: elegir unos programas, instalarlos, escribir un adaptador que les pase bytes y comprobar que funcionan con una entrada válida. Cada grupo repite este paso en cada artículo, y cada grupo elige de forma distinta. Así es difícil comparar los resultados y difícil reproducirlos.

Quería hacer este paso una vez y hacerlo bien. Para cada formato y lenguaje, Parsarium busca en los repositorios de paquetes, verifica los parsers que encuentra con un control válido, los ordena por adopción y prepara un harness con versiones fijadas para los que pasan. El resultado es un conjunto de targets que puedes inspeccionar, volver a ejecutar y citar.

Para qué sirve.

Para comparar fuzzers y generadores de pruebas sobre los mismos targets. Para comprobar cuántas implementaciones de un formato aceptan o rechazan una entrada dada. Para estudiar cómo cambia el comportamiento de los parsers entre lenguajes. Para enseñar: el manual usa Parsarium en todos sus ejercicios.

También sirve como punto de partida para investigar en seguridad. Fandango puede generar un corpus a partir de la gramática de un formato, ese corpus se puede pasar por todos los parsers del formato con un solo comando, y cualquier target puede entrar directamente en una campaña de AFL++.

0x0020un target

Qué contiene un target.

Cada target ejecutable vive en projects/<format>/<language>/<package>/. Tomando como ejemplo el target PNG de Pillow:

Versión fijada
pillow 13.0.0, instalado desde un archivo de bloqueo con el hash de su código fuente registrado.
API de entrada
La llamada documentada que analiza los bytes, aquí Image.open(), Image.load() e Image.getpixel(). La E/S genérica de archivos o la detección de tipo MIME no cuentan.
Control válido
controls/png/red-green.png, una imagen de 71 bytes con un píxel rojo y uno verde.
Salida esperada
Lo que el parser debe devolver con el control: width 2, height 1 y los dos píxeles RGBA.
Harness Docker
Un Dockerfile sobre una imagen base fijada y un harness que lee una entrada e imprime lo que observó el parser.
Registro de verificación
El ID de la imagen, las versiones de la cadena de herramientas, los hashes de los archivos, la salida observada y cuántas líneas del código fuente del parser cubrió el control.
Fuzzing
Una imagen para AFL++ con su propio registro de feedback, además del motor de fuzzing propio del lenguaje (Atheris en Python).

0x0030selección

Cómo se eligen los parsers.

El catálogo avanza celda a celda, un formato × lenguaje cada vez, y se queda con los paquetes verificados más adoptados de cada celda, hasta el límite que fija el protocolo de selección. Un parser entra cuando es de código abierto, tiene una versión fijada y analiza bytes locales mediante una API documentada con un resultado observable y propio del formato. Se admiten wrappers, y se registra la familia de parser que hay debajo.

Los paquetes se ordenan con una sola métrica de adopción por celda, normalmente las descargas del repositorio, y solo frente a otros paquetes de la misma celda. Las APIs de la biblioteca estándar se verifican igual y se listan aparte. Se guardan todas las búsquedas, sus resultados y las pistas sin resolver, así que puedes ver exactamente cómo se construyó una celda. Las reglas completas están en el protocolo de selección.

0x0040cuaderno

0x0050cita

Cómo citar Parsarium.

Si usas Parsarium en un artículo, cita la versión del paquete que instalaste (parsarium --version) o el commit que usaste. Si trabajas con un subconjunto, incluye también el ID de selección del banco.

@misc{parsarium,
  author       = {Zamudio Amaya, Jos{\'e} Antonio},
  title        = {Parsarium: An Open Testbed of Real Parsers},
  year         = {{{YEAR}}},
  howpublished = {\url{https://parsarium.com}},
  note         = {Commit {{COMMIT}}}
}

0x0060contacto

Cómo contribuir.

Las sugerencias de parsers, formatos o correcciones son bienvenidas como issues en GitHub. Si encuentras un bug en un parser usando Parsarium, notifícalo primero al proyecto original, a través de su política de seguridad si la tiene. Las notas de ética y uso responsable (en inglés) explican cómo depurar y comunicar lo que encuentres, y cómo pueden pedir los mantenedores que se modifique o retire un paquete. Para colaboraciones de investigación, puedes encontrarme en pepezamudio.com.
