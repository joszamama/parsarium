Glosario.

Los términos que usa este manual, con una definición breve y el capítulo donde se explica cada uno.

0x00A8términos

AFL++
Un fuzzer guiado por cobertura. Cada target ejecutable de Parsarium tiene una imagen para AFL++. Cap. 5
API de entrada
La función documentada que ofrece un paquete para analizar el formato, como png_image_begin_read_from_file. Cap. 3
API estándar
Un parser incluido en la biblioteca estándar o el runtime de un lenguaje, como image/png de Go. Se verifica como los paquetes y aparece por separado. Cap. 4
Arista
Una transición entre dos puntos del código. AFL++ cuenta aristas en su mapa para medir la cobertura. Cap. 5
Celda
Un formato en un lenguaje, como PNG en Rust. Parsarium tiene 80 celdas. Cap. 1
Control
Una entrada válida y pequeña con una salida esperada conocida, que sirve para verificar que un target funciona. Cap. 3
Corpus
Un conjunto de entradas: las semillas que recibe un fuzzer, la cola que construye o un conjunto generado que se vuelve a pasar por los targets. Cap. 7
Familia de parsers
El código que realmente lee el formato detrás de un paquete. Muchos paquetes pueden compartir una familia. Cap. 4
Gramática
Una descripción de las partes de una entrada, su orden y su anidamiento. Cap. 2
Harness
El pequeño programa que lee una entrada, llama a la API documentada del parser e imprime lo que observó. El harness de cada target se ejecuta en una imagen Docker fijada. Cap. 3
ID de selección
Un identificador que el banco deriva de una lista ordenada de targets. Junto con el commit de Parsarium, fija un conjunto de targets. Cap. 9
Pista
Un candidato que todavía no ha pasado todas las comprobaciones: un resultado de búsqueda en el catálogo, o un fallo o bloqueo guardado en una campaña. Cap. 8
Puente
El componente que registra la cobertura del código fuente del parser en Go, Java, JavaScript, Python o PHP y la escribe en el mapa de AFL++. Cap. 5
Ranking de adopción
La posición de un paquete según una métrica de popularidad, como descargas o estrellas, entre los paquetes de la misma celda. Cap. 4
Registro
Un registro JSON de lo que pasó: un registro de verificación para un target, un registro de ejecución para una entrada, un resumen para un lote. Cap. 3
Request smuggling
Un ataque que aprovecha que dos parsers HTTP no se ponen de acuerdo sobre dónde termina una petición. Cap. 6
Restricción
Una regla que relaciona partes de una entrada, como un campo de longitud que coincide con el tamaño de los datos o una suma de comprobación que coincide con los bytes que cubre. Cap. 2
Ruta de paquete
Un paquete o una API estándar junto con su API de entrada. Es la unidad que se cuenta en el catálogo. Cap. 1
Semilla
Una entrada de la que parte una campaña de fuzzing. Por defecto, el control del target. Cap. 7
Target
Una ruta de paquete verificada con un harness Docker ejecutable. Cap. 3
Testing diferencial
Enviar la misma entrada a varias implementaciones y comparar sus respuestas. Cap. 6
Tipo de feedback
Cómo informa un target de su cobertura a AFL++: con aristas compiladas o con un puente para un lenguaje concreto. Cap. 5
