CAPÍTULO 1 · EL ACUERDO

Un formato le dice al programa qué esperar.

Un parser recibe una entrada e intenta reconocer una estructura. El formato describe las partes posibles y su orden; el programa elige una API y una implementación para leerlas. Un control válido nos da un ejemplo concreto que debería funcionar.

Por eso la primera pregunta práctica de Parsarium es ¿qué programa y qué API de entrada recibirán este archivo, texto o flujo? El mismo formato puede llegar a muchos programas con código distinto detrás de la API.

Gramática

Las reglas que organizan una entrada. Pueden describir bloques binarios, tokens de texto, elementos anidados o un mensaje de protocolo.

CAPÍTULO 2 · LA GRAMÁTICA

Tres entradas pequeñas, tres estructuras distintas.

Estos son los controles válidos del ejercicio. Observa que el parser debe hacer más que comprobar un nombre de archivo.

PNGBloques

Un PNG comienza con una firma. Cada bloque siguiente tiene longitud, tipo, datos y suma de comprobación. IHDR indica las dimensiones; IDAT contiene los datos de imagen comprimidos.

firma→IHDR→IDAT→IEND
Pregunta para el parser: ¿qué dimensiones y píxeles describen esos bloques?
SVGÁrbol de elementos

SVG es XML. Un elemento raíz <svg> contiene formas y atributos. El navegador construye un árbol de elementos antes de que inspeccionemos el ancho, alto y los rectángulos.

<svg width="2" height="1">├─ <rect fill="#ff0000">└─ <rect fill="#00ff00">
Pregunta para el parser: ¿qué elementos y atributos aparecen?
PNM ASCIITokens

En una imagen PNM P3, los tokens de texto indican el valor mágico, las dimensiones, el máximo de canal y las muestras RGB. Los espacios separan tokens, pero los números también deben comprobarse.

P3→2 1→255→RGB × 2
Pregunta para el parser: ¿coinciden las muestras con el tamaño declarado?

La gramática ayuda a entender la entrada. El siguiente capítulo ejecuta un decodificador y muestra lo que observó ese programa.

CAPÍTULO 3 · PRUEBA UN PARSEO

Inspecciona la estructura antes del resultado.

Carga PNG, SVG o PNM ASCII. Ejecuta parse para ver la gramática encontrada en el control. El resultado permanece oculto hasta que elijas result. Este ejercicio usa decodificadores del navegador o didácticos; los objetivos Docker enlazados usan las bibliotecas reales.

CAPÍTULO 4 · LECCIONES

Qué demuestra un parseo correcto.

El control establece un punto de partida.

Una entrada válida muestra que la API elegida llega a código específico del formato y produce el resultado esperado. No describe todas las entradas que acepta el parser.

Estructura y resultado son observaciones distintas.

Un archivo puede tener partes reconocibles y, aun así, un programa puede interpretarlas de otra forma. Inspecciona la gramática y los campos o la salida que expone el parser.

El feedback pertenece al programa.

La cobertura indica qué líneas o aristas de una implementación se ejecutaron con esa entrada. Sirve para estudiar el programa; un formato no tiene cobertura propia.

Las comparaciones necesitan las mismas reglas.

Fija la versión, la API de entrada, el control y el harness. Registra las familias de parsers compartidas para no confundir dos nombres de paquete con dos motores independientes.
