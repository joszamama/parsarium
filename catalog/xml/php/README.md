# XML / PHP — pilot

**Status:** pilot_ten_selected_search_bounded; incomplete. 10 verified third-party paths, 4 verified standard APIs, 10 verified Docker harnesses.

Pilot cell at the ten-path ceiling. PROTOCOL.md lets a libxml2-family wrapper qualify as a package API with its parser family identified, so sabre/xml is counted with family libxml2 (shared with the standard XMLReader path). symfony/dom-crawler is counted under the same wrapper rule: its package-own scope is Crawler navigation and XPath/namespace mapping over a libxml2 DOMDocument, not tokenizing, and its Xdebug package lines differ by only one post-parse line between the two controls, so its AFL++ feedback comes from a native overlay (source-built PHP 8.5.12 and libxml2 2.15.4, allowlist limited to libxml2 parser.c/parserInternals.c/SAX2.c and ext/dom document.c plus ext/libxml) running the same Crawler harness, where the controls differ in 357 stable tuples, all arising while addXmlContent parses; its downloads are mostly HTML crawling uses. jms/serializer stays excluded because it maps an already parsed SimpleXML tree onto a target class model. symfony/serializer maps a DOMDocument through XmlEncoder::decode; its Xdebug package lines are separate from 359 stable native parser-time AFL tuples, and its whole-component downloads mostly reflect other encoders. It drops the root name and descendant namespace declarations. veewee/xml preserves qualified names and per-element xmlns declarations but groups siblings; mtownsend/xml-to-array loses namespace URIs, declarations and attribute prefixes. Both have package-owned array mapping and parser-only native libxml2 AFL feedback, not new tokenizer families. prewk/xml-string-streamer is excluded after a pinned two-control probe showed raw byte slicing only. laravie/parser is excluded because Reader::load is simplexml_load_file and Document::parse only maps that tree onto a caller schema, similar to excluded jms/serializer. saloonphp/xml-wrangler parses twice through veewee XMLReader and DOMDocument; its raw-name Element DTO loses namespace URI resolution and the nested empty-default undeclaration on the valid order control. Its 414 stable native AFL tuples are parser-derived, while package-own Xdebug lines are separate. pear/xml_parser (XML_Parser 1.3.8, abandoned on Packagist, last release 2019) qualifies as a libxml2-family SAX package path (displaced at the ceiling, see below): it creates and configures the ext/xml parser itself (xml_parser_create without a namespace separator, case folding, handler binding, string or 4096-byte stream feeding, free), so its raw-name summary is checked against an expat non-namespace oracle, with xmlns declarations as attributes and the documented $folding property set to false. Its coverage image source-builds PHP 8.5.12 and libxml2 2.15.4 with Xdebug 3.5.3 and LLVM coverage, so one run records 56 package lines plus ext/xml and libxml2 lines. Like laravie/parser, every AFL tuple that differs between its controls (299) also differs under a bare xml_parser_create/xml_parse baseline with the same handler object; unlike laravie, its own role is driving the parse rather than mapping an already parsed tree, so it qualifies with that limit stated. PHP 8.5 deprecates its xml_set_object() and xml_parser_free() calls; the notices are recorded. orchestra/parser is excluded with laravie/parser: its pinned source only extends laravie's Reader and Document with Laravel container wiring. jtrumbull/xml-parser is excluded after a pinned probe showed decode() is a bare SimpleXML JSON round trip. The smaller libxml2-family wrappers (alex.oleshkevich/fast-xml-parser, atk14/xmole, arc/xml) remain unresolved, as does the own-code lead watoki/dom. sabre/xml drops xmlns declarations and text in mixed-content elements by design, so its summary omits namespace declaration counts. Both coverage images use Ubuntu PHP 8.5.4 with libxml 2.15.2; both AFL++ overlays use the source-built PHP 8.5.12 and libxml2 2.15.4. The search covers the first 100 hits of five Packagist queries; controls are two small UTF-8 namespace-aware documents without DOCTYPE. Standard paths: XMLReader::XML, DOMDocument::loadXML, simplexml_load_string and xml_parser_create_ns/xml_parse are four PHP 8.5.12 runtime APIs over the same source-built libxml2 2.15.4, counted separately from the third-party paths and not ranked; DOMDocument::loadXML and simplexml_load_string take the control as an in-memory string, and their AFL++ overlays instrument only libxml2 parser.c/parserInternals.c/SAX2.c plus ext/dom document.c or ext/simplexml simplexml.c. SimpleXML exposes no separate text nodes, so its summary merges mixed-content character data per element (neither control has any); simplexml.c also holds the traversal methods, which the parse-only fuzz target does not call. xml_parser_create_ns/xml_parse is the only push-parser entry point (xmlCreatePushParserCtxt/xmlParseChunk through ext/xml/compat.c's expat-style SAX callbacks, no tree); its summary comes from event handlers with case folding off and a "\x01" namespace separator, the controls go in one final chunk, and its AFL++ overlay instruments libxml2 parser.c/parserInternals.c/SAX2.c plus ext/xml xml.c and compat.c. ext/xml has no comment handler (comments reach the default handler) and reports user-defined entity references unexpanded to the default handler, which the harness rejects. On 2026-11-18 every snapshot hit with at least pear/xml_parser's downloads that had no lead row was classified (registry-snapshot.json classification_2026_11_18, 48 rows). Four libxml2 DOM loaders were verified from it: querypath/querypath 3.0.5 (7,319,575; last release 2016, PHP 8.5 deprecations kept off output), laminas/laminas-xml 1.8.0 (3,988,633; guard facade like Python's defusedxml, successor of the uncounted zendframework/zendxml), simplesamlphp/xml-common v3.0.8 (3,504,693; Dom\XMLDocument loader of the SimpleSAMLphp stack) and imangazaliev/didom 2.0.1 (2,799,556; mostly HTML use, XML through Document::TYPE_XML). Each returns a namespace-aware DOM, so both controls are compared with the full namespace-aware expat summary; each package's own Xdebug lines are identical on both controls, so like Parsel and pear/xml_parser they are wrapper paths whose input-dependent AFL++ tuples (360-362) all arise while libxml2 parses, checked against a bare loader baseline with the package's options. With them the cell has eleven qualified paths; pear/xml_parser (1,819,294) is eleventh and is displaced at the ceiling, its row and receipts archived in ceiling-displaced.json. digitickets/lalit (2,446,737) and gravitypdf/querypath (2,098,757, a maintained QueryPath fork with 45% line overlap) would also rank below the tenth path and were not built. Excluded from the classification: hassankhan/config (SimpleXML JSON round trip, as jtrumbull), codeception/lib-xml (test support), php-soap/xml (SOAP helpers over veewee/xml), zendframework/zendxml (predecessor), XML-RPC/SOAP protocol libraries, schema- or format-specific readers, writers and non-XML packages.
