# XML / PHP — pilot

**Status:** pilot_three_selected_search_bounded; incomplete. 3 verified third-party paths, 4 verified standard APIs, 3 verified Docker harnesses.

Pilot cell, three verified third-party paths. The earlier zero count wrongly excluded libxml2-family wrappers; PROTOCOL.md lets a wrapper qualify as a package API with its parser family identified, so sabre/xml is counted with family libxml2 (shared with the standard XMLReader path). symfony/dom-crawler was reassessed under the same wrapper rule and counted: its package-own scope is Crawler navigation and XPath/namespace mapping over a libxml2 DOMDocument, not tokenizing, and its Xdebug package lines differ by only one post-parse line between the two controls, so its AFL++ feedback comes from a native overlay (source-built PHP 8.5.12 and libxml2 2.15.4, allowlist limited to libxml2 parser.c/parserInternals.c/SAX2.c and ext/dom document.c plus ext/libxml) running the same Crawler harness, where the controls differ in 357 stable tuples, all arising while addXmlContent parses; its downloads are mostly HTML crawling uses. jms/serializer stays excluded because it maps an already parsed SimpleXML tree onto a target class model. symfony/serializer maps a DOMDocument through XmlEncoder::decode; its Xdebug package lines are separate from 359 stable native parser-time AFL tuples, and its whole-component downloads mostly reflect other encoders. It drops the root name and descendant namespace declarations. The other libxml2-family wrappers (veewee/xml, mtownsend/xml-to-array, saloonphp/xml-wrangler, laravie/parser, orchestra/parser, pear/xml_parser and smaller ones) were not evaluated by the cutoff and remain unresolved, as do the own-code leads prewk/xml-string-streamer and watoki/dom. sabre/xml drops xmlns declarations and text in mixed-content elements by design, so its summary omits namespace declaration counts. Both coverage images use Ubuntu PHP 8.5.4 with libxml 2.15.2; both AFL++ overlays use the source-built PHP 8.5.12 and libxml2 2.15.4. The search covers the first 100 hits of five Packagist queries; controls are two small UTF-8 namespace-aware documents without DOCTYPE. Standard paths: XMLReader::XML, DOMDocument::loadXML, simplexml_load_string and xml_parser_create_ns/xml_parse are four PHP 8.5.12 runtime APIs over the same source-built libxml2 2.15.4, counted separately from the third-party paths and not ranked; DOMDocument::loadXML and simplexml_load_string take the control as an in-memory string, and their AFL++ overlays instrument only libxml2 parser.c/parserInternals.c/SAX2.c plus ext/dom document.c or ext/simplexml simplexml.c. SimpleXML exposes no separate text nodes, so its summary merges mixed-content character data per element (neither control has any); simplexml.c also holds the traversal methods, which the parse-only fuzz target does not call. xml_parser_create_ns/xml_parse is the only push-parser entry point (xmlCreatePushParserCtxt/xmlParseChunk through ext/xml/compat.c's expat-style SAX callbacks, no tree); its summary comes from event handlers with case folding off and a "\x01" namespace separator, the controls go in one final chunk, and its AFL++ overlay instruments libxml2 parser.c/parserInternals.c/SAX2.c plus ext/xml xml.c and compat.c. ext/xml has no comment handler (comments reach the default handler) and reports user-defined entity references unexpanded to the default handler, which the harness rejects.
