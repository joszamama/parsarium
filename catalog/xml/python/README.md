# XML / Python — pilot

**Status:** pilot_ten_third_party_one_standard_verified_bounded_search; incomplete. 10 verified third-party paths, 1 verified standard APIs, 10 verified Docker harnesses.

Ten verified third-party paths, in PyPI Stats last_month order (2026-11-17; Genshi 2026-11-18): lxml 437,507,754; beautifulsoup4 315,320,831; defusedxml 270,848,271; xmltodict 113,615,896; xmlschema 7,391,962; parsel 3,699,459; pyquery 1,326,240; untangle 310,666; Genshi 188,414 (captured one day later); jxmlease 118,785. Only lxml and xmltodict own a distinct parser engine binding: lxml/libxml2 2.15.4 backs beautifulsoup4 (recover=True), parsel (SafeXMLParser, recover=True) and pyquery (default XMLParser); CPython pyexpat/Expat 2.10.0 backs xmltodict, Genshi (genshi.input.XMLParser in namespace mode), defusedxml (guarded pure-Python ElementTree XMLParser), untangle (SAX via DefusedExpatParser), xmlschema (ElementTree.iterparse) and jxmlease (its own pyexpat parser). The wrappers' own Python lines are the same on both valid controls for defusedxml, xmlschema, parsel, pyquery and jxmlease, so their input-dependent AFL++ feedback is shared-parser feedback from libxml2 parser.c or Expat, labelled as such. untangle and jxmlease run with namespace processing off: untangle mangles qualified names and is checked against a projected lxml oracle; jxmlease reports raw names as written and is checked against the expat non-namespace raw-name oracle and an lxml raw-name projection, not against expanded names. pyquery's contents() walk returns no comments or processing instructions. lxml, beautifulsoup4, parsel and pyquery AFL feedback excludes parser.c lines 8700-8720 (address-sensitive attribute hash lookups). Genshi 0.7.12 (checked 2026-11-18) comes from a search for XML parsers whose package names lack 'xml' (template and markup toolkits, SOAP and XMPP stacks): its documented XMLParser runs pyexpat in namespace mode, matches both shared namespace-aware outputs exactly, and its input-dependent AFL++ feedback is mainly shared Expat feedback (669 Expat features, 631 tuples; 4 Genshi handler lines). That search excluded suds-community (internal, undocumented suds.sax parser of a SOAP client) and Twisted's words.xish.domish (XMPP stream element builder, a protocol library) and kept xmltodict-rs (16,768; Rust quick-xml family) as a lead below the tenth path. RapidXml 2.1.4's parse_cdata is undocumented (sdist re-read 2026-11-18). A bounded PyPI Simple-index name search (queries xml, expat, etree, sax, xpath, pugixml, rapidxml; first 100 alphabetical hits each, 379 hits, 376 unique) and the top-15,000 PyPI download list filtered for XML-related names surface no qualifying path beyond the other nine above the metric floor. Higher-download leads were excluded with reasons in leads.json: writers, XPath engines, HTML parsers, typed or caller-schema mappers (xsdata, pydantic-xml, xml-python), Scrapy (same Selector as parsel), wrappers over selected parsers (xmltojson, pandas-read-xml), a closed GraalVM native image (saxonche), a tree-sitter grammar, a C++-only package, a tree diff tool, schema-specific readers, an SDK helper without a documented parse API (alibabacloud-tea-xml), and the DRF XML parser, which fails the shared control. The two native bindings found below jxmlease are not counted: RapidXml 2.1.4's documented RapidXml(bytes) route drops CDATA and fails on the order control's euro character reference (only an undocumented parse_cdata=True keyword parses both), and pygixml's license adds a GitHub-star usage condition. The name search lists projects alphabetically and carries no download metric, so packages below the top-15,000 list that were not named by a query or documentation may exist. PyPI Stats package downloads are not XML-specific use. The controls exercise valid UTF-8 XML 1.0 namespace structures without DOCTYPE, not full XML conformance.
