# SQL / PHP — pilot

**Status:** pilot_eight_selected_search_bounded; incomplete. 8 verified third-party paths, 0 verified standard APIs, 8 verified Docker harnesses.

Eight verified PHP SQL paths after a bounded Packagist search (13 queries, 445 hits, 256 unique; round 1 on 2026-11-17 used three queries, round 2 added four, round 3 on 2026-11-18 added sql, sqlite parser, pgsql parser, sql tokenizer ast, sql statement parser and query parser sql) and Packagist total downloads for 35 targeted leads, captured 2026-11-17. phpmyadmin/sql-parser 6.0.1, greenlion/php-sql-parser v5.0.0, soundintheory/php-sql-parser 1.0, sad_spirit/pg_builder v3.3.1, flow-php/postgresql 0.48.0, flow-php/pg-query-ext 0.48.0, crodas/sql-parser v0.1.5 and bleksak/sqlite-toolkit 1.0.4 parse both valid controls into structures that give the oracle summary. soundintheory is a 2013 fork of the Google Code predecessor of greenlion (shared PHP-SQL-Parser lineage, separate monolithic code: 54.3% of its normalized statements occur in greenlion v5.0.0). Later greenlion forks (manticoresoftware, tsukasa, processfast, aitradeinc, michabbb) share 84-99.5% of normalized statements with greenlion and are excluded as near-identical forks or older snapshots; this cut-off is a curation judgment. crodas/sql-parser has a weak metric (2,490 lifetime downloads). flow-php/pg-query-ext is a PHP C extension over libpg_query 18.0.0 (PostgreSQL grammar, shared family with the C libpg_query path): its coverage and AFL++ feedback come from LLVM-instrumented and allowlisted native sources (ext/pg_query.c, gram.c, scan.c, parser.c) in a source-built PHP 8.5.12, and its MIT licence is pinned from the flow-php/flow monorepo because the subtree-split archive has no LICENSE file. flow-php/postgresql is counted under the wrapper rule as a second path of the same libpg_query family: its sql_parse() calls the extension's pg_query_parse_protobuf() and decodes the tree into its own protoc-generated AST classes with the pure-PHP google/protobuf runtime, and its package PHP lines differ between the controls (Xdebug, 163 parse-time lines), while its native AFL++ tuples are those of the extension. sqlftw/sqlftw is proprietary. iamcal/sql-parser ranks higher but parses only CREATE TABLE schemas, and the doctrine, jdorn and nilportugues packages are formatters. This is not a top-ten ranking. greenlion and soundintheory treat the whole input as one statement; pg_builder parses one statement per call, so its adapter cuts the input at its own Lexer's ';' tokens. PDO and SQLite3 prepare are engine APIs with no syntax tree. Two valid controls establish only the tested dialect-neutral subset. Round 3 found no further high-adoption parser: its plausible hits are a greenlion-based Laravel builder converter (rexshijaku/sql-to-laravel-builder), statement splitters and clause-string managers (nextras/multi-query-parser, rstoetter/csmartsqlstatement-php), schema-only parsers (calebdw/pg-schema-parser over pg_builder, maghead/sqlite-parser), an INSERT-only parser and a table-name extractor. inilim/sqlite-parser was re-checked on 2026-11-18 and its only release still has no licence text; subapp/sql stays blocked by Composer security advisories, which were not overridden. bleksak/sqlite-toolkit 1.0.4 (round-3 hit, 14 lifetime downloads, the weakest metric in the cell) is a hand-written SQLite 3.54 state-machine parser with its own typed AST; its README says most of the code was AI generated, and its parse entry is documented in docs/spec rather than the README. The cell stops at eight of ten because no qualifying lead remains after 13 bounded queries: the two unresolved leads cannot be verified (inilim/sqlite-parser has no licence text in its only release or repository; subapp/sql needs a Composer advisory override), and every other recorded lead is a formatter, query builder or converter, statement splitter, schema-only parser, proprietary package, near-identical greenlion fork or predecessor name.
