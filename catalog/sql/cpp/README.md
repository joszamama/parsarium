Two verified C++ SQL paths, one ranked by popcon and one by the GitHub-star fallback. Search: the shared Debian popcon source-name search (names containing 'sql', first 100 of 229 by rank) plus targeted lookups in the same pinned snapshot (duckdb, hsql/hyrise, gdal, kdb, libreoffice, sqlitebrowser, sqlitestudio, antlr4-cpp-runtime, soci and poco, captured 2026-11-17; qgis, futuresql, mysql-9.7, firebird4.0, firebird3.0, apache-arrow, mysql-connector-c++, sqlsmith and usql on 2026-11-18); vcpkg and Conan Center; the GitHub search 'sql parser language:C++' (discovery only) and known project leads (ZetaSQL, ClickHouse); and, under the C and C++ GitHub-star fallback (2026-11-18), bounded GitHub repository searches with stars:>=100 recorded in the registry snapshot. Selected: DuckDB 2.0.0 (Debian source duckdb, 40 installations) parses both valid controls with its built-in PEG grammar through duckdb::Parser, without a database or client context, into SQLStatement trees that give the oracle summary; the adapter reports DuckDB's count_star node for COUNT(*) as count. GoogleSQL 2026.11.2 (google/googlesql, formerly google/zetasql; 2,642 stars, Apache-2.0) is the star-fallback path: a tagged upstream release of a format-specific parser repository with at least 100 stars may fill slots left after the popcon path, ranked separately and never compared with popcon counts. It parses both valid controls with googlesql::ParseNextStatement and default LanguageOptions into an AST that gives the oracle summary. Metric caveats: DuckDB's popcon count is very small and counts installs of the whole engine, not use of its parser; its parser is a public header of an engine whose C++ API is described upstream as internal. GoogleSQL's stars cover the whole repository (parser, analyzer, reference implementation, Java and Go front ends), not installs or parser use; upstream calls the parser API semi-public because parse trees are not stable. Exclusions: higher-ranked C++ sources are wrappers, applications with internal parsers, a runtime without a grammar, or parsers that cannot read the INSERT control or need a connection (GDAL OGR SQL, KDb). qgis's QgsSQLStatement has no GROUP BY or INSERT, and futuresql is an asynchronous QtSql wrapper without a parser. mysql-9.7, firebird4.0, firebird3.0, apache-arrow, mysql-connector-c++, sqlsmith and usql are servers or engines with internal grammars, libraries without an SQL parser, a query generator, and a Go client that only shares the usql name. No other C++ source package in the snapshot has a documented SQL syntax-tree API. vcpkg and Conan Center list C++ SQL builders, ORMs, wrappers and clients but no SQL parser library. hsql (hyrise/sql-parser) has a documented AST API but no Debian source or development package in the pinned snapshot, and under the star fallback (813 stars) it has no tag or release. cybergarage/usql (55 stars) and sqltoast (33) have no Debian, vcpkg or Conan package and are below 100 stars (recorded as unresolved_no_primary_metric next to hsql); ClickHouse's parser is internal to its server; sqlcheck is a regex anti-pattern checker; SQLines and constexpr-sql have no tag. Evidence is in leads.json. The cell stops at two paths, not ten. Two valid controls establish only the tested dialect-neutral subset.
