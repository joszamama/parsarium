# JSON / Python — pilot

**Status:** pilot_ten_selected_search_bounded; incomplete. 10 verified third-party paths, 1 verified standard APIs, 10 verified Docker harnesses.

Ten positive-signal Python JSON third-party paths pass valid nested object and array controls with source-level parser coverage and AFL++ feedback: pydantic 2.14.3 (1,139,429,690 PyPI Stats last-month downloads), jiter 0.19.0 (421,162,504), orjson 3.13.0 (218,014,317), json5 0.17.3 (50,036,028), simplejson 4.3.0 (49,365,386), ijson 3.6.0 (46,615,664), msgspec 0.22.0 (39,138,375), ujson 6.1.0 (29,543,889), dirtyjson 1.0.8 (5,671,026) and hjson 3.1.0 (4,411,122). Pydantic embeds Jiter 0.18.0; standalone jiter uses Jiter 0.19.0 through a distinct package API. These are shared-family paths, not independent parsers, and their package downloads are not combined; orjson shares the yyjson C syntax-parser family but this pilot measures its Rust deserializer, not vendored C source lines. ijson uses the asserted yajl2_c backend, with pinned YAJL C tokenizer and Python extension coverage; its source-built embedded YAJL -O0 route differs from the official Linux wheel linkage and optimisation, and its other backends are untested. msgspec uses its own C JSON decoder in _core.c through untyped msgspec.json.decode; its source-built clang -O0 path differs from the official GCC wheel, typed decoding is untested, and JSON decoder sections are counted separately from other codecs in the same file. ujson uses its own UltraJSON C decoder with vendored double-conversion C++ for fractional numbers; both controls equal an exact CPython json oracle tree, and duplicate-key and edge-number behavior is recorded from source, not tested. json5 is a pure-Python JSON5 superset parser (glop-generated PEG parser.py plus lib.py conversion) that never calls the standard json module; json5.loads on bytes, on text and json5.load on a stream give the exact type-tagged CPython json oracle tree for both controls, with 668 covered package lines and stable feedback differing by 27 parser.py lines and 27 AFL++ tuples. It accepts JSON5-only syntax, so it does not reject non-RFC 8259 input, and its downloads mainly reflect JSON5 configuration use. dirtyjson and hjson are pure-Python decoders of simplejson-derived lineage (dirtyjson calls its loader a drastic rewrite of the simplejson loader; hjson says it is based on simplejson), so with the selected simplejson path they form one shared lineage of three separate code bases, not three independent parsers. dirtyjson.loads and hjson.loads on bytes and text, and their load on a stream, give the exact type-tagged CPython json oracle tree for both controls with the standard json module blocked; dirtyjson covers 156 package lines (129 in loader.py) with stable feedback differing by 14 lines and 14 AFL++ tuples, hjson 159 lines (152 in decoder.py) differing by 4 lines and 4 tuples. Both accept non-RFC 8259 input (dirtyjson is lenient, hjson parses the Hjson superset), and their downloads include non-JSON configuration and extraction use. The bounded PyPI Simple index search (six project-name queries, first 100 alphabetical hits each) and a top-15,000 download list used only as a discovery aid found 22 further leads: json5, dirtyjson and hjson are selected, 9 are excluded (json-repair returns the standard json.loads result on valid input and documents its own repair parser, skip_json_loads=True, only for input known to be invalid; pydantic-core is the same binary as the pydantic path; pandas, pyarrow and polars are tabular readers; srsly, partial-json-parser and commentjson delegate to ujson or CPython json; jsonnet evaluates a language) and 10 remain unresolved, all with fewer downloads than hjson, the tenth selected path, so none could enter the ten-path ceiling. python-rapidjson 1.26 (4,066,455) and pysimdjson 8.0.0 (679,340) pass every gate but have fewer downloads than dirtyjson and hjson, so they fall outside the ten-path ceiling; their catalog rows, verification records and receipts are kept in ceiling-displaced.json. These ten are not a definitive top ten by the metric. Python standard json is separately verified.
