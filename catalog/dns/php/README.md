# DNS / PHP — pilot

**Status:** pilot_five_verified_search_bounded; incomplete. 5 verified third-party paths, 0 verified standard APIs, 5 verified Docker harnesses.

Pilot cell: five PHP paths verified, react/dns, daverandom/libdns, pear/net_dns2, utopia-php/dns and jdwx/dns-query, ranked by Packagist total downloads; the cell stays below ten because no further Packagist package with a documented message-bytes API and its own decoder was found. daverandom/libdns's php-fuzzer blocker (the interceptor rewrite breaks one class constant) is resolved by loading that single class file unmodified in the fuzz entry only. jdwx/dns-query is a Net_DNS2 1.x fork that shares 6.0% of its distinct source lines with pear/net_dns2 2.x. react/dns, daverandom/libdns and utopia-php/dns drop the Z, AD and CD bits (z reported as 0). Excluded: amphp/dns, spatie/dns and remotelyliving/php-dns as resolvers or wrappers; purplepixie/phpdns, which parses only inside its socket client; mikepultz/netdns2, the same repository as pear/net_dns2 (identical v2.0.7 commit) and not counted twice; the other hits of the first-100 'dns' Packagist search, which are resolvers, format adapters over LibDNS, Net_DNS2 1.x forks or unreleased packages. Packagist searches for dns wire, decoder, protocol, server, resolver, client, query and mdns (first 100 each; registry-snapshot.json round3_search) found resolvers or clients that decode only inside their network calls (dapphp/torutils, ljpc/pure-php-doh-client, arrayaccess/dns-client, rafalmasiarek/dns-resolver), packages built on the selected react/dns, LibDNS or Net_DNS2 (danog/php-rtc-mdns, chieftools/dns-resolver, quasarstream/mdns, sharkydog/mdns, noglitchyo/dealdoh, thruster/dns, domraider/libdns), a DNS server (hoa/dns), unreleased or non-wire packages (zanphp/dns-client, mezon/dns-client, ipokbr/dns), and cboxdk/dns, whose undocumented decoder drops the header ID, flags and questions. yswery/dns remains a lead (public decoder, no documentation). Searches beyond the registry windows (registry-snapshot.json round4_discovery) covered GitHub repository searches (dns parser, dns packet, dns message, topic:dns, rfc1035, dns codec, dns decoder, dns wire format; first 100 each, mapped to Packagist packages), Packagist reverse dependencies of daverandom/libdns, pear/net_dns2 and react/dns, further Packagist text searches (rfc1035, doh, nameserver, resource record, dns tunnel, dns packet, dns protocol, dns encoder) and awesome lists; every published hit was already recorded or is a resolver, client, DoH middleware or format adapter over a selected decoder. Further searches (registry-snapshot.json round6_discovery and round6_targeted) covered Packagist terms bonjour, zeroconf, dnssd, dns-sd, multicast dns, dnssec, edns, rdata, dns response, dns record, kaitai, dns packet parser and domain name system, Packagist dependents of utopia-php/dns and jdwx/dns-query (none) and yswery/dns, GitHub code searches for hand-written header and compression decoders, and GitHub repository searches for PHP DNS servers, clients, libraries, mDNS, DoH and resolvers. Most repositories with their own decoders are not on Packagist; the published ones are a framework-internal client (kakserpom/phpdaemon), a JSON DoH resolver (sirmonti/doh), an RDATA-only codec (yocto/yoclib-dns), dig or resolver wrappers and forks, and a DNSSEC validator over PSL's internal decoder. No Kaitai Struct DNS package is published. Each verified path parses the two valid controls (a query and a response with compressed CNAME/A/AAAA/MX answers) to the hand-written oracle summary, has library source coverage and stable AFL++ feedback that differs between the controls. Two valid controls do not establish EDNS0, DNSSEC, TXT, authority/additional or malformed-input behaviour. Package-level adoption metrics include non-DNS use; the remaining leads are unverified, and the cell is not a definitive top ten.
