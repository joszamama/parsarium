# DNS / Python — pilot

**Status:** pilot_ten_verified_search_bounded; incomplete. 10 verified third-party paths, 0 verified standard APIs, 10 verified Docker harnesses.

Pilot cell at the ten-path ceiling: dnspython, Twisted (twisted.names.dns), mitmproxy (mitmproxy.dns), dpkt, dnslib, py3dns, namespy, pydns3, dns-messages and pyasyncdns, ranked by PyPI Stats last-month downloads (namespy's, pydns3's and pyasyncdns's counts captured 2026-11-18, the others 2026-11-17). Twisted's and mitmproxy's counts cover the whole networking framework and interception proxy, not only their DNS packages; importing mitmproxy.dns pulls in mitmproxy's flow model and its full dependency set, but an instrumented run of both controls created no socket in either image. py3dns has no API reference (README and bundled unpacker tests only) and its import reads /etc/resolv.conf as a local file. Excluded from the registry search hits and targeted lookups (registry-snapshot.json round2_targeted): pycares (c-ares channel API, no bytes parser); scapy, under this pilot's no-socket rule (its import opens AF_NETLINK sockets); zeroconf, impacket and pypacker, which fail the response control (MX or AAAA/CNAME rdata not decoded by the library); pyshark, which wraps tshark; pydns, py3dns's predecessor. The PyPI name search read all 1,074 names containing 'dns', not only the first 100 alphabetically (registry-snapshot.json round3_search), and looked up the plausible ones: PythonDNS and microdns wrap dnslib, dnsq wraps dnspython, dnspython3 and dnspythonchia are dnspython's older line and fork, dnslib3 is a dnslib fork (65.9% shared lines, same import name), aiodnsresolver keeps its parser private, asyncdns2 and dnsmock are resolvers. async-dns and dns-client decode messages through exported but undocumented classes and stay leads. Searches beyond the registry windows (registry-snapshot.json round4_discovery) covered GitHub repository searches (dns parser, dns packet, dns message, topic:dns, rfc1035, dns codec, dns decoder, dns wire format; first 100 each, mapped to PyPI names), awesome lists, packet and binary-format libraries and mDNS libraries, ranked only by the same PyPI Stats source (round4_targeted). They found namespy (selected; its name lacks 'dns'). netius stays a lead (decoder inside its DNS client module, header flags kept as raw octets); pyatv, kamene, aiozeroconf and kydns fail the response control by source inspection (MX, and for some CNAME/AAAA, not decoded); construct's 2.5 gallery struct follows no compression pointers; strangle wraps the obsolete BIND 8 libbind; scapy-python3 is a placeholder; PyPCAPKit, pycrate and hachoir have no DNS parser. On 2026-11-18 PyPI's classifier search (Topic :: Internet :: Name Service (DNS)) answered automated requests with a JavaScript client challenge and was not bypassed, so ecosyste.ms keyword listings of PyPI packages were used instead (registry-snapshot.json round5_discovery: dns, rfc1035, mdns, dns-parser, dns-packet, packet-parser, dns-message, dnssec, dns-server, dns-client, dns-resolver, dns-proxy, nameserver, domain-name-system, dnslib, dnspython, multicast-dns, llmnr), ranked only by the same PyPI Stats source (round5_targeted). They found pydns3 (selected: pydns over the same author's pystructs3) and PyAsyncDNS (selected: a transport-agnostic codec shipped with an asyncio client/server and exfiltration tool). Excluded from those listings: nanodns (raw RDATA), compactdns (MX preference misread), devns (requests only), polardns (pentest server), minidns (Twisted), greendns, tinydns, dns-local and foghorn (dnslib), dnspx and recursive-resolver (dnspython), latterdns (datagram proxy), wa1kpcap (PCAP frames, header only), urllib3-future (internal resolver helpers) and cryptoparser (DNSSEC RDATA only). Each verified path parses the two valid controls (a query and a response with compressed CNAME/A/AAAA/MX answers) to the hand-written oracle summary, has library source coverage and stable AFL++ feedback that differs between the controls. Two valid controls do not establish EDNS0, DNSSEC, TXT, authority/additional or malformed-input behaviour. Package-level adoption metrics include non-DNS use; the remaining leads are unverified, and the cell is not a definitive top ten.
