# DNS / Java — pilot

**Status:** pilot_seven_verified_search_bounded; incomplete. 7 verified third-party paths, 0 verified standard APIs, 7 verified Docker harnesses.

Pilot cell: seven JVM paths verified, netty-codec-dns, dnsjava, pcap4j-core, minidns-core, SIDN dnslib and the Scala libraries dns4s-core_2.13 and taxonomy-scodec_2.13, ranked by deps.dev direct dependents summed over releases (a weak signal; Pcap4J's count covers its whole multi-protocol artifact). The cell stays below ten because no further qualifying path was found in the bounded search. Scala libraries count in this Java cell when they document a JVM API, as Scala and Kotlin libraries such as circe-yaml and ktoml do in other Java cells; dns4s is ranked by its Scala 2.13 coordinate only. Netty leaves A/AAAA as raw records (the harness formats the decoded bytes) and its DnsQuery has no AA/TC/RA/RCODE. Pcap4J's names come from DnsDomainName.decompress, whose leading '.' for pointer-only names the harness drops, and its coverage and AFL++ feedback are scoped to its DNS classes. MiniDNS decodes AD and CD but not the reserved Z bit; dns4s decodes none of Z, AD and CD. Round 2 added targeted deps.dev lookups for the plausible Maven search hits: the Netty backport and Netty 5 alpha are the selected Netty family, ph-dns and spotify dns wrap dnsjava, happy-dns keeps its parser package-private, and ninio-dns and the Direct Project DNS are network applications. Round 3 added Maven searches for dns packet, parser, protocol, decoder, mdns and jmdns: ApacheDS's DnsMessageDecoder was run and throws on the CNAME answer (no CNAME decoder), otavia's DNS codec 0.4.5 has only a query encoder, JmDNS keeps its message reader in its implementation package and skips MX, and Pekko's DNS codec is internal API. Round 4 searched beyond the registry windows (registry-snapshot.json round4_discovery): GitHub repository searches for Java, Kotlin and Scala (dns parser, dns packet, dns message, topic:dns, rfc1035, dns codec, dns decoder, dns wire format; first 100 each, mapped to Maven Central coordinates), awesome lists, framework and Netty-adjacent codecs, and mDNS libraries, ranked only by the same deps.dev count (round4_targeted). It found the Scala library taxonomy-scodec_2.13 (selected). Excluded: Akka's DNS codec (internal API, as Pekko's), OkHttp's DoH DnsRecordCodec (Kotlin internal, A/AAAA only), Hola (no CNAME/MX decoding), native-mdns (announcer), scout (built on taxonomy), taxonomy-scodec_3 (Scala 3 build) and netty-dns-support (unreleased Netty fork); packet-dissector-lib-kmp is published only on JitPack, so it has no deps.dev metric. Round 6 (registry-snapshot.json round6_discovery and round6_targeted) paged Maven Central Solr searches to the end of each result set and added an artifact-id prefix search (a:dns*), mDNS, DNS-SD, DNSSEC, DoH, zeroconf and bonjour terms, packet and capture libraries (jnetpcap, pkts, jxpacket, jxnet, Ardikars pcap, Kaitai Struct) and GitHub searches for Clojure, Groovy, mDNS, DNS-SD and Java/Kotlin DNS libraries. It found SIDN Labs' dnslib (selected, 13). Excluded: the zeroconf mDNS library (package-private reader, no CNAME/MX), a JSON DoH resolver (io.zrz.rtcore.sip), dnsjava extensions and copies (tuweni-dns-discovery, dnsjnio, org.dnsjava:dnsjava 2.0.6, mdnsjava) and happy-dns-java, whose public parseResponse keeps only A/CNAME answers; dnskotlin, kendamasoft dns-client, relaycorp doh, halo and tinydnssd have zero direct dependents. No published Clojure, Groovy, Kaitai or packet-library DNS decoder qualified, so the cell stays at seven. Each verified path parses the two valid controls (a query and a response with compressed CNAME/A/AAAA/MX answers) to the hand-written oracle summary, has library source coverage and stable AFL++ feedback that differs between the controls. Two valid controls do not establish EDNS0, DNSSEC, TXT, authority/additional or malformed-input behaviour. Package-level adoption metrics include non-DNS use, and the cell is not a definitive top ten.
