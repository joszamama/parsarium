# TOML / Python — pilot

**Status:** pilot_seven_selected_search_bounded; incomplete. 7 verified third-party paths, 1 verified standard APIs, 7 verified Docker harnesses.

Bounded TOML search captured 2026-11-17: 1 query, 100 recorded hits (100 unique), at most 100 per query; the PyPI Simple index has no relevance order and the name filter matches unrelated names, so the leads come from targeted lookups observed 2026-11-18: all 409 PyPI names containing "toml", the toml-lang wiki lists, the toml-test-matrix parser list, 56 binding-style PyPI name lookups and vendored or sub-module TOML parsers in larger libraries (pip, setuptools, poetry-core, pipenv, dynaconf, msgspec, cattrs, mashumaro, pyserde, pydantic-settings; all are copies of, or delegate to, decided families). Seven third-party paths pass both valid controls with exact hand-written typed trees, parser-scoped coverage and AFL++ feedback, three identical runs per control each: tomlkit 0.15.2 (591,365,129 PyPI Stats last-month downloads; 845 package lines, 408 in parser.py; controls differ by 401 AFL++ tuples), tomli 2.5.0 (263,305,223; 284 lines, 259 in _parser.py; controls differ by 137 tuples), rtoml 0.14.0 (1,380,894; source-built PyO3 extension with Rust LLVM coverage: 768 toml_parser 1.1.5 lines, 488 underlying toml 1.1.8 lines; controls differ by 1,242 AFL++ tuples over the toml, toml_parser and toml_datetime crate sources), pytomlpp 1.1.0 (43,243; source-built pybind11 extension with LLVM coverage: 922 vendored toml++ lines, 729 in parser.inl; controls differ by 715 tuples), tomlrt 2.3.3 (519,376; own pure-Python format-preserving reader), tomlclass 0.4.1 (2,652; own pure-Python parser) and pytoml11 0.0.5 (200; a pybind11 wrapper over a vendored toml11 4.2.0, sharing the toml11 family with the selected C++ toml11 path; source-built with clang 16 and measured with LLVM region coverage). tomli is the same code family as the standard tomllib API (a vendored copy), so the two are not independent; the hand-written trees are tomli's independent check. Only tomli's pure-Python wheel is measured, not its mypyc-compiled wheels. tomlkit is an independent style-preserving parser; its downloads mostly reflect Poetry and other tool installs. rtoml shares the Rust toml_parser family with the selected Rust toml and toml_edit paths (the same toml_parser 1.1.5 release), and pytomlpp shares the toml++ family with the selected C++ toml++ path (a vendored post-3.4.0 snapshot); both are measured as coverage-instrumented source builds, not the official wheels. tomlclass (2,652) and pytoml11 (200) are weak adoption evidence. The standard tomllib API passed both controls on a host run. Two valid controls establish only the tested TOML 1.0.0 subset; malformed input, huge documents and TOML 1.1 features are untested. The cell cannot reach 10 on these routes: toml 0.10.2 (145,147,540) fails typed-scalars because it drops the fractional seconds of the local time 00:32:00.25; pytoml 0.1.21 (337,081) rejects the hexadecimal integer and qtoml 0.3.1 (2,002) the fractional-second offset date-time of typed-scalars; tomli-w is a writer; and toml-rs 0.4.3 (18,062) gives both exact typed trees but is excluded: its toml, toml_parser and toml_edit come from lava-sh/toml git forks of toml-rs/toml whose sources share 94-97% of their lines with the crates.io toml_parser 1.1.5 and toml 1.2.1 releases, a near-identical fork of the toml_parser family already selected through rtoml. toml.py, toml-python, contoml/prettytoml and libtoml fail a control or cannot parse its syntax; dom-toml (238,660) delegates to the standard tomllib; tomli-rs, rustoml, spanned-toml, tomli-null and toml-tools are wrappers or forks of selected families; tombi and taplo are CLI binaries; fasttoml has only pre-releases. No further PyPI TOML parser with a positive metric was found.
