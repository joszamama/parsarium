# YAML / PHP — pilot

**Status:** pilot_two_verified_bounded_search; incomplete. 2 verified third-party paths, 0 verified standard APIs, 2 verified Docker harnesses.

Two verified PHP YAML paths from different families. symfony/yaml v8.1.11 parses both schema-neutral valid controls through the documented Yaml::parse(string) with Yaml::PARSE_OBJECT_FOR_MAP into exact ordered typed trees; without that flag mappings become PHP arrays and {} cannot be told from []. Xdebug covers 570 package lines (365 in Parser.php); the parser-line AFL++ bridge repeats identically three times per control and the controls differ by 61 lines and 61 tuples, all in Parser.php, Inline.php and Unescaper.php. pecl/yaml 2.3.0 (the PECL yaml extension, libyaml family) parses both controls through the documented yaml_parse() with a YAML_MAP_TAG callback that keeps mappings as stdClass; LLVM covers 537 extension lines (252 in parse.c) and 1,331 libyaml lines, and the native AFL++ overlay (yaml.c/parse.c/detect.c and libyaml reader/scanner/parser) repeats identically five times per control with 897/869 tuples, 196 differing. Its Packagist metric counts only PIE installs through Packagist, not PECL or distribution-package installs. mustangostang/spyc 0.6.3 is excluded: it leaves \u and \t escapes undecoded, drops the final line break of clip-chomped block scalars, misreads '|-' with more-indented lines and returns '...' as a sequence item. dallgoot/yaml 1.0.1 (372,583) is excluded: it leaves \" and \t escapes and the single-quoted '' escape undecoded. The bounded Packagist search used 'yaml' (first 100 of 1,954 hits) and, in round 2, 'yaml parser', 'yaml-parser', 'yml' and 'spyc' (first 100 each). Round 2 probed 17 further packages on both valid controls; none qualifies: wrappers and config loaders over symfony/yaml (grasmash/yaml-expander, hassankhan/config, jbzoo/data) return PHP arrays and lose {} versus [], nette/neon parses NEON rather than YAML, Spyc forks and own parsers (wp-cli/mustangostang-spyc, maikuolan/common, xp-forge/yaml, horde/yaml and smaller ones) fail escapes, aliases or block scalars, and tbela99/yaml passes but is a symfony/yaml 5.1 fork (916 of 1,164 distinct source lines shared). Other config, serializer, OpenAPI and front-matter hits that call symfony/yaml were not recorded as separate leads. Round 3 (2026-11-18) added no PHP lead: no package in the recorded searches beyond the 25 decided leads presents its own YAML parser, the remaining hits being configuration, serializer, OpenAPI or front-matter packages whose descriptions name symfony/yaml (not re-probed individually), and every independent parser probed so far fails escapes, aliases or block scalars. Mapping layers that return PHP arrays cannot pass order.yaml ({} versus []). The cell therefore stays at two. Packagist downloads are package adoption, mostly transitive through Symfony and Laravel, not YAML parsing frequency. Two valid controls do not establish tags, merge keys, multi-document streams, YAML 1.1-only scalars or malformed-input behavior.
