# YAML / PHP — pilot

**Status:** pilot_three_verified_bounded_search; incomplete. 3 verified third-party paths, 0 verified standard APIs, 3 verified Docker harnesses.

Three verified PHP YAML paths from different families. symfony/yaml v8.1.11 parses both schema-neutral valid controls through the documented Yaml::parse(string) with Yaml::PARSE_OBJECT_FOR_MAP into exact ordered typed trees; without that flag mappings become PHP arrays and {} cannot be told from []. Xdebug covers 570 package lines (365 in Parser.php); the parser-line AFL++ bridge repeats identically three times per control and the controls differ by 61 lines and 61 tuples, all in Parser.php, Inline.php and Unescaper.php. pecl/yaml 2.3.0 (the PECL yaml extension, libyaml family) parses both controls through the documented yaml_parse() with a YAML_MAP_TAG callback that keeps mappings as stdClass; LLVM covers 537 extension lines (252 in parse.c) and 1,331 libyaml lines, and the native AFL++ overlay (yaml.c/parse.c/detect.c and libyaml reader/scanner/parser) repeats identically five times per control with 897/869 tuples, 196 differing. Its Packagist metric counts only PIE installs through Packagist, not PECL or distribution-package installs. mustangostang/spyc 0.6.3 is excluded: it leaves \u and \t escapes undecoded, drops the final line break of clip-chomped block scalars, misreads '|-' with more-indented lines and returns '...' as a sequence item. dallgoot/yaml 1.0.1 (372,583) is excluded: it leaves \" and \t escapes and the single-quoted '' escape undecoded. The bounded Packagist search used 'yaml' (first 100 of 1,954 hits) and, in round 2, 'yaml parser', 'yaml-parser', 'yml' and 'spyc' (first 100 each). Round 2 probed 17 further packages on both valid controls; none qualifies: wrappers and config loaders over symfony/yaml (grasmash/yaml-expander, hassankhan/config, jbzoo/data) return PHP arrays and lose {} versus [], nette/neon parses NEON rather than YAML, Spyc forks and own parsers (wp-cli/mustangostang-spyc, maikuolan/common, xp-forge/yaml, horde/yaml and smaller ones) fail escapes, aliases or block scalars, and tbela99/yaml passes but is a symfony/yaml 5.1 fork (916 of 1,164 distinct source lines shared). Other config, serializer, OpenAPI and front-matter hits that call symfony/yaml were not recorded as separate leads. Round 3 (2026-11-18) added no PHP lead: no package in the recorded searches beyond the 25 decided leads presents its own YAML parser, the remaining hits being configuration, serializer, OpenAPI or front-matter packages whose descriptions name symfony/yaml (not re-probed individually), and every independent parser probed so far fails escapes, aliases or block scalars. Mapping layers that return PHP arrays cannot pass order.yaml ({} versus []). Round 3 therefore left the cell at two. Packagist downloads are package adoption, mostly transitive through Symfony and Laravel, not YAML parsing frequency. Two valid controls do not establish tags, merge keys, multi-document streams, YAML 1.1-only scalars or malformed-input behavior. Round 4 (2026-11-18) added purrphp/yaml 1.0.0 (Packagist lifetime 1,088, a very weak proxy for a 2026 release), found by a GitHub 'yaml parser' search for PHP repositories: its own pure-PHP YAML 1.2 line reader, block Parser, InlineParser and CoreSchema, with no symfony/yaml or libyaml code. YamlStreamSingle::fromString builds a node model that keeps mappings distinct from sequences; the harness walks it in source order and types scalars with the package's documented CoreSchema::resolve. Xdebug covers 551 package lines (122 in Parser/Parser.php); the parser-line AFL++ bridge repeats identically three times per control and the controls differ by 57 lines and 57 tuples. Round-4 discovery (GitHub 'yaml parser' and 'yaml' searches for PHP repositories, then Packagist lookups) found purrphp/yaml and 11 further leads, all excluded (leads.json, round4-lead-probes.json): a document splitter (webignition/yaml-document-set-parser), a renamed Spyc copy (eureka/component-yaml), symfony/yaml and ext-yaml wrappers or configuration loaders (yalesov/yaml, pieter/yaml, rindow/rindow-module-yaml, nigatedev/yaml, sndsgd/yaml, atphp/yaml), an unreleased Symfony Yaml derivative (klausi/yaml_comments), a token-tree library without a value API (aeliot/yaml-token), and taufik-nurrohman/y-a-m-l, which fails order.yaml.
