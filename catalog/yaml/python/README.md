# YAML / Python — pilot

**Status:** pilot_ten_verified_bounded_search; incomplete. 10 verified third-party paths, 0 verified standard APIs, 10 verified Docker harnesses.

Ten verified third-party paths in PyPI last_month order: PyYAML 6.0.3 (1,227,712,536); PyYAML CSafeLoader (libyaml) 6.0.3 (1,227,712,536); ruamel.yaml 0.19.1 (177,667,165); ruamel.yaml.clib 0.2.15 (69,289,256); srsly 3.0.1 (24,260,205); rapidyaml 0.15.2 (224,758); yamlcore 0.1.1 (92,413); yaml-rs 0.1.6 (80,054); ryaml 0.5.1 (23,629); libfyaml 1.0.0rc2 (407). PyYAML (pure SafeLoader) and ruamel.yaml (YAML(typ='safe', pure=True)) are pure-Python loaders with Python line coverage of their own package. PyYAML CSafeLoader is a separate route of the same PyPI package (its metric is the PyYAML package value, not a split) whose scanner/parser is libyaml 0.2.5, built from source with LLVM coverage and linked statically into _yaml. ruamel.yaml.clib is ruamel.yaml's C loader package with its own metric; its vendored C is an older libyaml snapshot (96.1% of distinct lines shared with libyaml 0.2.5), so it shares the libyaml family with the CSafeLoader path. srsly.yaml_loads is a labelled wrapper over the same pure ruamel.yaml route; its own lines are identical on both controls. rapidyaml is the Python binding of the C++ rapidyaml parser (same family as the C++ cell path): the pinned sdist is built with its own SWIG/CMake build and LLVM coverage, and because ryml keeps scalars as untyped text the adapter types plain scalars with YAML 1.2 core-schema patterns (adapter-side typing). yamlcore.CoreLoader is a labelled wrapper over PyYAML's pure BaseLoader with its own YAML 1.2 core resolver/constructors. ryaml is a PyO3 binding over serde_yaml 0.9.34 and unsafe-libyaml 0.2.11 (Rust transpilation of libyaml), built from its sdist with Rust source coverage; it shares the serde_yaml/unsafe-libyaml family with Rust cell paths and the libyaml family with the C routes. yaml-rs is a PyO3 binding with its own Rust loader over granit-parser events (saphyr-parser / yaml-rust lineage, shared with Rust cell paths), built from its sdist on a pinned nightly with Rust source coverage; its Cargo.lock pins git dependencies by revision. libfyaml is the python-libfyaml binding of the libfyaml C library (1.0.0-rc2, same family as the C cell libfyaml path), built from the pinned release tag with LLVM coverage; every PyPI release of the binding is a pre-release, so the newest (1.0.0rc2) is pinned, and its 407 downloads are a very weak proxy. Native routes report LLVM regions of the parser C; Python routes report executed lines; each has three identical AFL++ runs per control that differ in scanner/parser sources. The bounded search (project name contains 'yaml'; first 100 alphabetical hits of 798, captured 2026-11-17) and named leads are recorded; remaining leads are in leads.json. A supplementary check of 13 named high-adoption PyPI projects outside that window (C routes, wrappers, forks, loader plugins; 2026-11-17) is recorded in registry-snapshot.json; strictyaml fails both controls, oyaml/yamlloader/yamlordereddictloader/pydantic-yaml are excluded as re-export or mapping layers, PyYAML-ft and ruyaml as identical or predecessor forks, rapidyaml was promoted in round 3, and yaml-rs remains an unresolved native lead. Round 3 added three native bindings (rapidyaml, yaml-rs and ryaml resolved through source builds with native coverage) and the libfyaml binding, reaching the ten-path ceiling; further named lookups are recorded (ruamel.yaml.clibz is byte-identical to ruamel.yaml.clib, poyo and yamlium fail the controls, msgspec/omegaconf/confuse/hiyapyco are mapping layers over PyYAML, yamale, pyaml and yamlpath are a validator, an emitter and a CLI). The bounded search window remains alphabetical, so other high-adoption packages may exist outside it. Package adoption is not YAML-specific use. The two controls cover a schema-neutral YAML 1.2 subset only, not tags, merge keys, multi-document streams, complex keys, YAML 1.1-only scalars or malformed input.
